# Frontend CheckStock

Сначала примени [checkstock-task-guide](../checkstock-task-guide/SKILL.md) для поиска действующего поведения. Структура интерфейса описана в [docs/architecture.md](../../../docs/architecture.md). Проверки клиентского кода описаны в [checkstock-testing](../checkstock-testing/SKILL.md).

## Размещение и стиль

- Предметные шаблоны размещай в соответствующем разделе `templates/`, JavaScript и CSS — в соответствующем разделе `static/`. Общие шаблоны находятся в `templates/layout/`, общий клиентский код — в `static/common/`.
- Сохраняй используемый в проекте способ сборки шаблонов через `string.Template`. Не вводи иной шаблонизатор для отдельной страницы.
- Для JavaScript и CSS следуй соглашениям соседних файлов: общей конфигурации форматтера для них нет. Не переформатируй целый файл ради локального изменения.

## Повторное использование компонентов

- Перед созданием шаблона, стиля или клиентского компонента найди похожий действующий элемент и его места использования. Переиспользуй или расширяй его, если назначение и поведение совпадают.
- При изменении общего компонента сохраняй его прежний контракт и поведение во всех существующих местах использования. Если новый сценарий отличается, вырази отличие явным параметром или отдельным компонентом; не меняй прежнюю логику скрыто.
- Не копируй одинаковые шаблоны и CSS-правила для новой страницы. Выделяй общую часть, когда она действительно общая и её выделение не усложняет существующие сценарии.
- После изменения общего шаблона, стиля или компонента проверь все страницы и сценарии, которые его используют.
