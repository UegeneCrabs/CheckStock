# Проверка изменений CheckStock

Сначала примени [checkstock-task-guide](../checkstock-task-guide/SKILL.md) для определения действующего контракта. Этот скилл задаёт правила проверки изменений backend и frontend, не повторяя их правила реализации.

## Тесты

- Для Python используй существующий набор `unittest` в `tests/`; для клиентского JavaScript — `node --test` с относящимися к изменению файлами `tests/*.cjs`. Соблюдай ограничение [checkstock-task-guide](../checkstock-task-guide/SKILL.md) на добавление постоянных тестовых файлов там, где оно применимо.
- Размещай Python-тест в `tests/` по пути проверяемого модуля относительно `app/`: для `app/application/wb_product_rating.py` — `tests/application/test_wb_product_rating.py`. Для вложенных каталогов добавляй `__init__.py`, чтобы `python -m unittest discover -s tests` находил тест. Не создавай `tests/app/`: при этой команде он перекрывает рабочий пакет `app`.
- Каждый новый или переписываемый тест строй в порядке Given → When → Then. Внутри метода явно разделяй блоки комментариями `# Given`, `# When`, `# Then`: подготовка условий, вызов проверяемого действия, затем утверждения об ожидаемом результате.
- Непосредственно перед методом пиши русский комментарий `# Тест-кейс: ...` с проверяемым сценарием и ожидаемым результатом. В начале метода добавляй докстринг с `Тест-кейс: ...` и отдельной формулировкой `Ожидается ...`.
- Проверяй наблюдаемое поведение и значимые ошибочные или граничные случаи. Не пиши тест, который лишь повторяет структуру реализации или ищет текст кода.
- Если меняется публичный тип, DTO или ответ API, проверяй связанные вызывающие сценарии. Если меняется общий шаблон, стиль или клиентский компонент, проверяй все существующие сценарии, которые его используют.
- Для изменений данных учитывай обе поддерживаемые СУБД: SQLite и PostgreSQL. Отмечай, если одна из них не была проверена.

## Команды и результат

- Сначала запускай относящиеся к изменению тесты через `python -m unittest discover -s tests -p 'test_<module>.py' -v`, затем при необходимости весь набор через `python -m unittest discover -s tests -v`. Для общих Python-проверок используй `python -m ruff format --check app scripts` и `python -m ruff check app scripts`; при изменении тестов проверяй Ruff также на их путях.
- Для клиентского кода запускай `node --test` с конкретными файлами `tests/*.cjs`, относящимися к изменению.
- Сообщай, какие команды прошли и что осталось непроверенным. Локальные тесты не подтверждают работу внешних API, браузерных интеграций или production.
