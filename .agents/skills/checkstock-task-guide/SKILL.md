# Документация и планирование задач CheckStock

Работай в корне репозитория CheckStock: его можно узнать по `app/main.py` и `docs/llm-wiki.md`. Скил относится только к этому проекту. Для задач, не связанных с поведением приложения (например, просмотр статуса Git), достаточно применить этот скил без чтения всей документации.

## Найти контекст

1. Прочитай [карту проекта](../../../docs/llm-wiki.md) и через [индекс](../../../docs/README.md) выбери документы по теме задачи. Не загружай все документы подряд.
2. Сверь существенные утверждения выбранных документов с текущими файлами `app/`, `scripts/`, `templates/`, `static/`, `tests/` и настройками запуска. Для HTTP-контракта проверь маршруты и DTO; при доступном работающем приложении можно дополнительно сверить OpenAPI.
3. Если документация и реализация расходятся, явно отметь расхождение. Текущее поведение определяй по коду, тестам, схеме БД и конфигурации; не выдавай историческое описание за действующий контракт.

## Спланировать новую задачу

Сначала сформулируй ожидаемый результат и границы задачи. Затем укажи затронутые модули и документы, последовательность изменений, проверку результата и конкретные неопределённости или риски. Для изменений данных проверь схему, миграцию и обратную совместимость; для складских операций — [контракт повторов и транзакций](../../../docs/f03-stock-transactions.md); для экономики — [полноту исходных данных](../../../docs/f05-economics-completeness.md).

Если пользователь просит только план, представь его без изменения кода. Если пользователь просит выполнить задачу, используй план для работы и доведи реализацию до проверки, не останавливаясь на описании плана. Записывай план в файл только по запросу пользователя или когда он нужен как рабочий артефакт задачи.

При изменении поведения обнови соответствующий тематический документ. Если меняются карта модулей или набор инструкций, обнови также `docs/llm-wiki.md` и `docs/README.md`.
