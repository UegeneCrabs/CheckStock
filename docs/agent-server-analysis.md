# Серверный анализ для GPT

Новые методы дополняют существующий API. Старые пути, фильтры и пагинация сохранены.
Изменения пока подготовлены локально; установка на рабочий сайт не выполнялась.

## getAnalyticsProductAnalysis

GET `/api/agent/v1/product-analysis`. Обязательны scenario, date_from, date_to.
Без store проверяются все магазины WB, разрешённые для необходимых источников.

| scenario | Проверка |
| --- | --- |
| stock_without_orders | Положительный наблюдаемый остаток без транзита и нулевые заказы за весь период |
| turnover_drop | ТО заказов ниже того же периода неделей ранее |
| drr_negative_roi | ДРР от нуля до drr_max включительно и отрицательный полный ROI из отчёта «Юниточная прибыль» |
| stock_impressions_drop | Положительный остаток и падение рекламных показов относительно предыдущего равного периода |
| active_low_ctr | Товар в активной кампании с CTR строго меньше ctr_below; подтверждённые свежесть статуса и покрытие периода |
| goal_gap | Заказы ниже равномерной цели по текущему ТЕГу: недельная цель / 7 × число дней выбранного периода |

compare_from/compare_to меняют базу только для turnover_drop и stock_impressions_drop.
Периоды должны иметь одинаковую длину, от 1 до 90 дней. Будущие даты запрещены.
goal_gap допускает только текущую неделю ПН–ВС: исторические цели не подменяются текущими.
Текущий день помечается незавершённым; почасовой истории эта доработка не создаёт.

manager сопоставляется на сервере по словам имени и фамилии независимо от порядка,
регистра и ё/е. Одно имя допустимо при единственном совпадении; несколько людей
возвращают 422 со списком доступных совпадений. code фильтрует ТЕГ, не ABC.
is_new использует признак новинки сайта. fulfillment доступен для сценариев стока;
при его выборе учитываются ФФ и FBS выбранного ФФ, без FBO/rFBS/транзита.

## Полнота и результат

Источники загружаются полностью внутри сервера один раз на магазин/период,
через существующие расчёты и чтение БД. GPT не обходит страницы исходных товаров.
Соединение выполняется по магазину и артикулу, рейтинг — по ТО заказов по убыванию,
неизвестные значения в конце. Имя берётся из доступных источников базы.

Итоги checked/matched/unknown/no_match относятся ко всей отфильтрованной выборке.
Пагинация limit/offset применяется только к готовому результату. include_unknown=true
включает непроверенные товары в страницы, unassessed_sample — не более 10 примеров.
Сбой источника исключает магазин из подтверждённого результата и добавляет failed_stores.

Для нулевых заказов и сравнений нужна запись с известными значениями за каждый день.
Отсутствие строки не считается нулём. Показатель completeness отражает выполненные
проверки, но не подтверждает реальное время остатков или полноту внешнего маркетплейса.
Сток — снимок, показы — рекламные; прибыль — расчётная, не подтверждённый финансовый итог.
Гипотезы и бизнес-оценка остаются задачей GPT; сервер возвращает факты и пробелы.

## Выпуск

Обновить сервер, схему Action из `/api/agent/v1/openapi.json` и инструкцию GPT.
Для сводных сумм используется отдельный getAnalyticsProfitSummary (см. agent-profit-summary.md).
Политика доступа остаётся текущей политикой API; отдельная отложенная ветка общего
доступа GPT не включается этой доработкой автоматически.
