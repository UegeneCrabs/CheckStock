# Чтение юнит-экономики без повторных расчётов

Оптимизация от 20.10.2026 относится к коду WB, Ozon и Яндекс Маркета.
Отчёт СПП исключён. Формулы, интервалы, правила полноты и приоритет ручных поправок
сохранены. Миграции, загрузка API и изменения сохранённых данных не требуются.

## Ozon

`app/ozon/advertising_read_index.py` строит индекс фактов по артикулу внутри каждого
дня и источника. Таблица и график передают расчётам факты нужного товара вместе
со всеми нераспределёнными фактами. Последние необходимы для признаков частичной
полноты расходов и показов. Метаданные снимка, недоступные виды рекламы, ошибки,
свежесть и оконные корректировки сохраняются.

Для формирования множества исходных типов рекламы достаточно одного представителя
каждой пары `adv_object_type/payment_type`. Исходные снимки и список кампаний в БД
не изменяются. Сводка нераспределённых расходов использует полные исходные данные.
Индекс рекламы существует в рамках одной сборки ответа.

Стартовый список юнит-экономики Ozon обновляется каждые 30 минут после первого
открытия. Интервал в секундах задаёт `CHECKSTOCK_OZON_PRODUCTS_CACHE_SECONDS`
(по умолчанию `1800`, в том числе в Docker Compose). Значение `0` отключает кэш
и таймер. Эта настройка применяется только к стартовому списку Ozon.
Кэш включается для полного списка с параметрами по умолчанию. После проверки доступа
сервер сверяет доступные магазины и фактические даты отчёта. Готовые байты JSON
хранятся в памяти одного процесса. Сервер хранит один вариант списка.
Карточка товара, фильтр магазина и пользовательский период читаются непосредственно из БД.

Срок отсчитывается с завершения успешной сборки. Повторные чтения его не продлевают.
При первом открытии или смене доступных магазинов либо дат запрос ждёт сборку
подходящего отчёта, если его ещё нет в кэше. Таймер веб-процесса запускает
одну фоновую сборку даже при отсутствии запросов. Период пересчитывается по
московской дате на момент сборки. Пока обновление идёт, запросы с теми же
магазинами и датами получают последнюю готовую версию. Обе версии JSON
заменяются вместе. После ошибки сохраняется предыдущий ответ того же периода.
Таймер повторяет попытку через настроенный интервал, а новый запрос к истёкшей
версии может инициировать её раньше. У каждого веб-процесса свой кэш и таймер.

Для стартового списка Ozon сервер выбирает gzip по заголовку `Accept-Encoding`
и добавляет `Vary: Accept-Encoding`. При включённом кэше каждая сборка сохраняет
исходный JSON и его gzip-копию. Повторные открытия получают готовые байты.
При выключенном кэше сервер сжимает ответ по запросу клиента. После распаковки
браузер получает прежний JSON.

## Яндекс Маркет

Расчёт одного товара читает источники по его артикулу. Для текущей экономики,
прибыли и целевой цены `current_sources` исключает архив `day-input:*` уже в SQL.
Обычный `sources` и контекст по умолчанию сохраняют этот архив: он нужен графику
для восстановления исторической цены и исходных данных.

Таблица заранее группирует историю, заказы и рекламу по артикулам. Сегодняшние
ручные поправки и исходные значения читаются одним `day_records` на магазин
с ограничением по отображаемым товарам. Приоритет единого дневного реестра над
старыми COMMON-записями и над `day-input` остаётся прежним. Сведения о загруженных
днях остаются общими для магазина: отсутствие строки товара на подтверждённом
пустом дне не становится пропуском.

## WB

Для карточки и графика воронка и реклама выбираются по нормализованному nmID;
история остатков — по полному артикулу. Полный каталог сохраняется для склеек
и сопоставления поставок. Покрытие дней и средние заказы для запаса остаются
магазинными. Необязательные фильтры репозиториев не меняют остальных потребителей.

Если за сегодня уже есть дневная запись, таблица не рассчитывает неиспользуемый
запасной снимок. Отчёты прибыли и целевой цены читают сохранённые входные параметры
через `inputs_only`, затем применяют прежний расчёт дня, фактическую полноту
источников и ручные поправки. Целевая цена ограничивает снимки товарами отчёта.

## Проверка выделенного выпуска

21 октября 2026 на временных SQLite и PostgreSQL 17 проверены фильтры
артикулов, включая кавычки, сохранение загруженных пустых дней и приоритет
дневного реестра с ручными поправками над прежними источниками. Проверки
использовали синтетические данные; внешние API и рабочие базы не вызывались.

При переносе Ozon на актуальный master требуется проверять индекс по каждому
товару вместе с нераспределёнными расходами, пустыми и неполными днями.
