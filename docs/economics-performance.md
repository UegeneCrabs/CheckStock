# Чтение юнит-экономики без повторных расчётов

Оптимизация от 20.10.2026 относится к коду WB и Яндекс Маркета.
Отчёт СПП исключён. Формулы, интервалы, правила полноты и приоритет ручных поправок
сохранены. Миграции, загрузка API и изменения сохранённых данных не требуются.

## Яндекс Маркет

Расчёт одного товара читает источники по его артикулу. Для текущей экономики,
прибыли и целевой цены `current_sources` исключает архив `day-input:*` уже в SQL.
Обычный `sources` и контекст по умолчанию сохраняют этот архив: он нужен графику
для восстановления исторической цены и исходных данных.

Таблица заранее группирует историю, заказы и рекламу по артикулам. Сегодняшние
ручные поправки и исходные значения читаются одним `day_records` на магазин
с ограничением по отображаемым товарам. Приоритет единого дневного реестра над
старыми COMMON-записями и над `day-input` остаётся прежним. Сведения о загруженных
днях остаются общими для магазина: отсутствие строки товара на подтверждённом
пустом дне не становится пропуском.

## WB

Для карточки и графика воронка и реклама выбираются по нормализованному nmID;
история остатков — по полному артикулу. Полный каталог сохраняется для склеек
и сопоставления поставок. Покрытие дней и средние заказы для запаса остаются
магазинными. Необязательные фильтры репозиториев не меняют остальных потребителей.

Если за сегодня уже есть дневная запись, таблица не рассчитывает неиспользуемый
запасной снимок. Отчёты прибыли и целевой цены читают сохранённые входные параметры
через `inputs_only`, затем применяют прежний расчёт дня, фактическую полноту
источников и ручные поправки. Целевая цена ограничивает снимки товарами отчёта.

## Проверка выделенного выпуска

21 октября 2026 на временных SQLite и PostgreSQL 17 проверены фильтры
артикулов, включая кавычки, сохранение загруженных пустых дней и приоритет
дневного реестра с ручными поправками над прежними источниками. Проверки
использовали синтетические данные; внешние API и рабочие базы не вызывались.
