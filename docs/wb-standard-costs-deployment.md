# Развёртывание сравнения ИУ и без ИУ WB

Ветка: `feature/new-report`. Изменения не слиты в master. Отчёт: `/sales/unit-economics-1c/reports/standard-costs`.

## Перед запуском

1. Сохранить резервную копию серверной БД и текущую ревизию приложения.
2. Развернуть ветку с её шаблонами и статикой. Не копировать локальную `.env`, SQLite, временные файлы и токены разработчика. Сервер продолжает использовать свою БД и свои секреты.
3. Обновить веб и `scheduler` штатным способом проекта. `init_db` создаёт таблицы `wb_standard_costs_sources` и `wb_standard_costs_snapshots`; отдельный импорт локальной базы не нужен.
4. Для автоматической работы установить `CHECKSTOCK_DISABLE_BACKGROUND_SYNC=0`. В «API и интеграции» включить задачу «WB: сравнение ИУ и без ИУ» и нужные магазины.
5. Проверить WB-токены всех магазинов: доступ к финансовым отчётам, аналитике хранения, карточкам и тарифам. Локально TRUSTHOME не проверен: токена нет.

## Загрузка и приёмка

Задача `wb_standard_costs_sync` загружает последние семь завершённых дней по Москве. При первом добавлении планируется запуск через минуту; далее — через четыре часа после окончания. Уже сохранённое расписание учитывается при перезапуске. Повторы после ошибки — через 5 и 15 минут. Можно запустить задачу вручную через интеграции. Это не фиксированный период 12–18 октября: даты будут зависеть от дня запуска.

Проверить `/healthz`, `/readyz`, состояние scheduler, историю задачи и даты снимков каждого магазина. Ошибка API не заменяет предыдущий снимок неполными данными. Если магазин не загрузился, проверить его результат отдельно.

Закупку, ФФ, налоги, рекламу, цены и выкуп отчёт читает через общий загрузчик калькулятора из серверной БД. Новая задача не заменяет существующие загрузки калькулятора/1С.

Проверить несколько артикулов против калькулятора, фильтры, сортировку, раскрытие расходов и подсказки. Прибыль с ИУ и без ИУ отличается только комиссией WB, логистикой и хранением. Для FBW без продаж хранение оценивается по дневной ставке за 90 дней. ИЛ=1 и обратный тариф 46/14 руб. — согласованные допущения. Неполные исходные данные остаются прочерками, а не нулями. В актуальной локальной проверке также выявлены товары каталога, не сопоставленные загрузчиком калькулятора; публикация сама по себе эту проблему не исправляет.

## Проверки ветки

`python -m unittest discover -s tests -p "test_wb_standard*.py" -q`

`node --check static/economics/wb/standard-costs.js`

Рефакторинг проверен точным сравнением 1606 строк до/после. Это не подтверждает полноту всех товаров: известные пропуски источников и сопоставления сохраняются.
