# Ежедневная резервная копия БД в Google Диск

Задача `database_backup_google_drive` находится на вкладке **Google Таблицы**
страницы `/admin/integrations?tab=google`: расписание, переключатель, ручной
запуск и история. Автоматический запуск выполняет существующий worker
`python -m app.jobs.worker` ежедневно в **08:00 Europe/Moscow**, независимо
от часового пояса ОС и фоновых выгрузок маркетплейсов. Если worker остановлен,
задача в это время не выполняется; сохранённый просроченный запуск обрабатывается
при следующем старте. Новая задача впервые планируется на ближайшие 08:00.

Это копия всей настроенной БД по состоянию на начало резервирования. Она не
закрывает экономические дни, не проверяет полноту заказов/рекламы и не подменяет
исторические расходы текущими. Параметры и сохранённая история уже входят в БД.
`.env`, `secrets/`, файлы других Docker-томов и роли PostgreSQL не копируются.
Релизные дампы в `/home/bd_backup` и скрипт их очистки не изменены.

## Настройки

| Переменная | Назначение |
|---|---|
| `CHECKSTOCK_BACKUP_ENABLED` | Разрешить автоматическую задачу; по умолчанию `0`. Ручной запуск доступен и при `0` |
| `CHECKSTOCK_BACKUP_DRIVE_FOLDER_ID` | ID папки на общем Google Диске |
| `CHECKSTOCK_BACKUP_DIRECTORY` | Каталог временных файлов и квитанций; локально `data/backups/database`, в Docker отдельный том |
| `CHECKSTOCK_BACKUP_PG_DUMP`, `CHECKSTOCK_BACKUP_PG_RESTORE` | Пути к PostgreSQL CLI; по умолчанию `pg_dump`, `pg_restore` |
| `CHECKSTOCK_BACKUP_TIMEOUT_SECONDS` | Таймаут операции создания/проверки; по умолчанию 7200 секунд |
| `CHECKSTOCK_BACKUP_HTTP_TIMEOUT_SECONDS` | Таймаут запроса Google; по умолчанию 180 секунд |

Используется ключ `CHECKSTOCK_GOOGLE_SERVICE_ACCOUNT_PATH`. Доступ Drive
получается отдельно, scopes существующих Google Таблиц не меняются. У папки
общего диска сервисному аккаунту нужны права добавления файлов; Google Drive API
должен быть включён в его проекте. Обычный личный «Мой диск» для прямой загрузки
от сервисного аккаунта не поддерживается из-за отсутствия собственной квоты.
PostgreSQL-клиент должен поддерживать версию сервера; Docker-образ включает
пакет `postgresql-client`.

## Создание и доставка

PostgreSQL сохраняется через `pg_dump --format=custom`; до отправки проверяется
оглавление `pg_restore --list`. SQLite копируется через online backup API с
соединением только для чтения источника, проверяется `PRAGMA quick_check` и
сжимается в `.sqlite.gz`. Создание, проверка и хеширование выполняются отдельным
дочерним процессом, не блокируя event loop. При отмене останавливается дерево
дочерних процессов. Рабочая БД не заменяется и не восстанавливается.

Дамп загружается блоками 8 MiB через resumable upload. ID файла и URI загрузки
сохраняются до отправки содержимого. Повтор запрашивает подтверждённую позицию;
завершившаяся загрузка проверяется по ID, размеру и серверной MD5. SHA-256 также
хранится в квитанции и метаданных файла. Токены и URI загрузки не выводятся в UI.
Квитанции и незавершённые файлы находятся в отдельном постоянном каталоге;
для файлов задаются права `0600`, для каталога `0700` на POSIX.

За одну московскую дату и одно подключение создаётся одна подтверждённая копия.
Повтор после успеха возвращает прежний ID. После подтверждения Google удаляются
только собственный временный архив и его pending-файл; квитанция остаётся.
При ошибке архив сохраняется для повтора. Автоматические повторы: через 5,
15 и 60 минут. На Google Диске нет удаления, перезаписи старых копий или срока
хранения. Для нового независимого бэкапа после успешного запуска нужна следующая
дата; ручная кнопка не создаёт дополнительные копии того же дня.

## Ручная проверка

Из корня проекта:

```shell
python -m scripts.ops.backup_to_drive --check
python -m scripts.ops.backup_to_drive
```

`--check` проверяет чтение папки и право добавлять файлы без создания архива.
Обычный запуск использует текущую настроенную БД и записывает ручной запуск
в общую историю. Код `0` означает проверенный успех либо уже созданную копию;
код `1` означает ошибку. Произвольный процесс CLI не включает расписание ОС.

Проверка структуры дампа не заменяет пробное восстановление: PostgreSQL
восстанавливается только в отдельную БД через `pg_restore`; SQLite — распаковкой
`.sqlite.gz` в отдельный файл с последующей проверкой и сравнением данных.

Код: `app/application/database_backup.py`, `app/dto/database_backup.py`,
`app/infrastructure/database_backup_store.py`,
`app/integrations/database_backup_drive.py`, `app/jobs/database_backup.py`,
`scripts/ops/create_database_backup.py`, `scripts/ops/backup_to_drive.py`.
