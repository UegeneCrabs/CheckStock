# Сводка для GPT

GET `/api/agent/v1/profit-summary`, операция `getAnalyticsProfitSummary`.
Обязательны date_from/date_to. Без store — все доступные магазины WB.
Необязательные compare_from/compare_to задают равный период сравнения;
по умолчанию используется непосредственно предшествующий период той же длины.
manager — явный фильтр, передаётся в исходный отчёт для обоих периодов.

ТО и общая маржа берутся из totals того же серверного отчёта «Юниточная прибыль».
Для товаров с положительным ТО используется его же функция расчёта итогов.
Ответ содержит одну строку на магазин; пагинации товаров нет.

- orders_amount — сумма ТО товаров с подтверждённым покрытием периода; null, если таких товаров нет.
- website_margin / website_margin_complete — общая маржа сайта и её полнота; при неполных данных маржа null.
- ordered_products_report_margin — сумма полностью рассчитанной маржи по товарам с подтверждённым положительным ТО.
- ordered_products_margin — та же сумма; неполная выборка помечается margin_complete=false. Если ни одного рассчитанного товара нет — null; подтверждённая пустая выборка при полном покрытии — 0.
- incomplete_margin_products / unknown_orders_products — причины неполноты.
- turnover_change_rub / turnover_change_percent — изменение ТО; при нулевой базе процент неизвестен.

Это расчётная маржа с ожидаемыми выкупами, не подтверждённая финансовая прибыль.
Пустой отчёт не считается подтверждённым нулём. Сбой одного магазина/периода
отмечается available=false и не скрывает остальные результаты. Текущий день
помечается незавершённым. Расчёты пока только WB; доступ проверяется как у отчёта.

Для выпуска обновить сервер, схему Action и инструкцию из
`/static/agents/agent-instructions.txt`. Рабочий сервер в рамках этой задачи не обновлялся.

Покрытие проверяется по сохранённым дневным данным заказов для каждого товара
выборки за каждый день периода. Допускается агрегат с точным совпадением обеих дат.
Товар без подтверждённого ТО исключается из обеих сумм. Товар с известным ТО,
но неполной маржой входит только в ТО. Частичные суммы маржи внутри одного
товара не прибавляются. При отсутствии подходящих данных сумма null, не 0.

orders_included_products / unknown_orders_products — включённые и исключённые
товары для ТО. margin_included_products — товары с положительным ТО и полной
маржой; margin_excluded_products — неизвестный ТО плюс неполная маржа у товаров
с положительным ТО. Товары с подтверждённым нулевым ТО не относятся к исключениям.
data_status: complete, partial или missing; data_message поясняет отсутствие данных.
GPT показывает суммы без оговорок о неполноте и предупреждающих значков.
Маржа понимается как сумма по товарам с расчётами. Счётчики исключений
и признаки полноты сохраняются в API для диагностики, выводятся по запросу.
Прирост сравнивает доступные суммы ТО обоих периодов, включая неполные
и разные выборки товаров. turnover_comparison_partial=true отмечает неполное
сравнение. Если одной суммы нет — прирост null. При нулевой базе разница
в рублях считается, процент остаётся null. available=true означает успешное получение отчёта.
