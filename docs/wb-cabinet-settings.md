# Почасовой коэффициент D кабинетов WB

В «Интеграции и выгрузки → Параметры кабинетов → WB» у каждого кабинета есть
таблица «Коэф D по часам». Значения сохраняются общей кнопкой «Сохранить»
отдельно для выбранного кабинета.

| Час (МСК) | D по умолчанию |
|---|---:|
| 8:00 | 0,18 |
| 9:00 | 0,23 |
| 10:00 | 0,30 |
| 11:00 | 0,36 |
| 12:00 | 0,42 |
| 13:00 | 0,48 |
| 14:00 | 0,54 |
| 15:00 | 0,60 |
| 16:00 | 0,66 |
| 17:00 | 0,71 |
| 18:00 | 0,76 |
| 19:00 | 0,81 |
| 20:00 | 0,87 |
| 21:00 | 0,92 |
| 22:00 | 0,96 |
| 23:00 | 1,00 |

Коэффициент действует с начала указанного часа до начала следующего по Москве.
С 00:00 до 07:59 используется 1. В анализаторе значение выбирается сервером
для текущего часа и кабинета товара; выбранная историческая неделя не меняет
дату блока сегодняшнего ТО. Формула сохраняется: `forecast = round(fact * D, 2)`.
При неизвестном факте прогноз остаётся `null`; подтверждённый ноль остаётся нулём.
От прогноза пересчитываются разница с планом и отклонение.

Ответ `/api/analytics/analyzer` содержит `coeff` каждой строки,
`coefficient_hour` (текущий час МСК) и `coefficient_valid_until` (ISO-время
следующей смены часа). Открытая видимая страница обновляет данные при смене
часа, сохраняя фильтры и черновики комментариев; скрытая обновляется при
возврате. Во время сохранения комментария обновление откладывается. После
ошибки автоматическая повторная попытка выполняется не чаще раза в минуту.

`GET /api/unit-economics-1c/cabinet-settings` и
`PUT /api/unit-economics-1c/cabinet-settings/{store_slug}` включают
`hourly_d_coefficients`: массив из 16 объектов `{hour, value}`. Каждый целый
час от 8 до 23 должен присутствовать ровно один раз. Значения конечные,
неотрицательные, не больше 1 000 000; сервер проверяет весь массив до записи.
Права совпадают с существующими правами изменения кабинета WB.

В `unit_economics_1c_cabinet_settings` добавлена nullable TEXT-колонка
`hourly_d_coefficients` с JSON. Миграция совместима с SQLite и PostgreSQL;
старым строкам с NULL и новым кабинетам DTO подставляет значения из
`WB_ANALYZER` в `app/core/constants.py`. Старые запросы без нового поля
сохраняют уже настроенные коэффициенты. Обновление комиссии команды из
Google Sheets также не меняет эту колонку.

Реализация: `app/dto/unit_economics_1c.py`,
`app/repositories/unit_economics_1c.py`, `app/analytics/analyzer.py`,
`static/economics/wb/cabinet-settings.js`, `static/analytics/analyzer.js`.

Проверено на временной SQLite: миграция старой таблицы и повторный запуск,
сохранение и разделение кабинетов, совместимость старых запросов, HTTP-права
и валидация, часовые границы по Москве, нулевой и неизвестный факт.
В headless Edge проверены форма, мобильная ширина, сохранение и повторное
открытие, режим чтения, автоматическая смена часа с сохранением поиска
и черновика. Существующие 41 unittest и Ruff прошли. Для PostgreSQL проверена
компиляция DDL; проверка на живой PostgreSQL и развёртывание не выполнялись.
