# Результат задачи: аналитика Яндекс Маркета

## Запрос и подтверждённые решения

Пользователь запросил для ЯМ три существующих инструмента аналитики WB: Анализатор, Эфемериды, Продажи по API. Сохраняются пользовательские возможности, дизайн и все исходные колонки. Экономика и исходные данные соответствуют площадке; Рейтинг товаров вне задачи. Push, релиз и деплой не запрашивались.

Приняты прямые решения пользователя:

1. Собственные почасовые коэффициенты D каждой площадки и магазина. До заполнения прогноз и зависимые разница/отклонение неизвестны; коэффициенты WB не копируются.
2. Все колонки WB сохраняются, неизвестное показывается «—» с причиной; подтверждённый ноль остаётся нулём.
3. Для ЯМ корзины показываются за исходную дату отчёта с явной подписью «дата отчёта Маркета; границы суток не подтверждены». Преобразования в московские сутки и обещания совпадения с датами заказов нет. Предварительность и задержка сохраняются в контракте.

## Итоговое внутреннее ТЗ и реализация

Критерии R 1–R 3 и относящиеся контракты сохранены в [тематическом документе](../yandex-analytics.md): полный каталог, точный артикул, исходные колонки/виды/фильтры/карточки/экспорты, даты и nullable-показатели, сегодняшнее ранжирование независимо от выбранной недели, история/комментарии/CAS, отдельный D и источники корзин/возвратов.

Аналитический ДРР использует валовые суммы заказов × датированный выкуп на общем покрытии с рекламой. Отмены не вычитаются повторно. Выкуп сегодняшнего снимка не заполняет неизвестную историческую дату. ROI/прибыль используют действующую экономику ЯМ с дневными inputs, overrides и версиями; юнитка не менялась. Net-факт завершённой недели эфемерид не меняет знаменатель ДРР. Известный ноль и отсутствие наблюдения различаются во всех трёх инструментах.

Добавлены собственные DTO, calculations/sources, application service/порт, infrastructure repository/UoW/ORM, router и jobs. Новые записи заметок, комментариев, D и ETL проходят application/UoW; основная запись, ревизия/coverage и подтверждение успеха атомарны. Новые таблицы добавляются metadata/create_all; старые WB/Ozon таблицы и данные не преобразуются.

Общие три шаблона/JS/models параметризованы через marketplace, apiBase, pageBase, storageKey, exportPrefix, labels и metricIdentity. WB сохраняет URL, preferences, CSV и размерную дедупликацию. ЯМ использует полный seller SKU; совпавшие артикулы двух магазинов/площадок не объединяются. Общий контракт устанавливался ЯМ первым; Ozon переиспользует его в своём отдельном контуре. В общем меню добавлены три самостоятельные страницы ЯМ.

Новые загрузчики сохраняют source-date toCart и полный snapshot возвратов FBY. Исходный API reports и устойчивый business/report limiter общий с текущим выкупом; DONE не равен полноте суток. Метаданные raw source-days позволяют today-first и пропуск свежих исторических дней. Неизвестные статусы/неполная пагинация/повтор возврата не публикуют новый success. Последний успех сохраняется при ошибке. Недельный сток фиксируется независимо по понедельникам после 00:05 МСК, immutable, без backfill сегодняшними остатками.

## Самопроверки первой попытки — исторические данные

- Python 3.13.5, имеющиеся Ruff/mypy/SQLAlchemy/FastAPI/Pydantic/uvicorn/httpx подтверждены без установки.
- SQLite: init дважды; реальные заметки/ревизии, CAS D и комментариев, два конкурентных писателя, rollback, immutable stock и сохранность последнего transit success при ошибке.
- PostgreSQL 17.5: те же реальные schema/CAS/rollback/reads/HTTP на отдельной временной БД ym_coder1; persisted limiter и funnel-days freshness проверены реальными SQL-транзакциями. Рабочая PostgreSQL не использовалась.
- HTTP: реальные FastAPI router→service→SQL с fixture-пользователем, все три data API и HTML-страницы, malformed даты/периоды/час/unknown store/inactive user. Fixture middleware заменял только аутентификационную границу; реальный login-поток отдельно не проверялся.
- Числовые probes: валовые 1000/отмены 300/выкуп 50%/реклама 100 дают ДРР 20%, две строки дают итог 15%, explicit buyout 0, пустое пересечение, CTR суммами, факты gross/net, исторические цена 80/100 и цель 0, null прогноза до D.
- ETL: official-shape fixtures, strict toCart, полный SKU, страницы/повторы return ID, все собственные кампании, unknown статусы, today-first missing/stale cache, отказ второго магазина, polling того же reportId, pre-reservation и монотонность persisted deadline, NO_DATA без success.
- Node: WB defaults/размерная дедупликация, полный SKU/изоляция магазинов, weighted ratios после отбора, CSV formula escaping, смена московской недели, Drafts при вводе во время pending request.
- Настоящий локальный браузер: Анализатор 4 строки,24 поля D и сохранение PUT, Эфемериды/история с autosave и read-only решениями, Продажи по API 2 отфильтрованные строки, CSV всех 7 дней при скрытых столбцах дней, карточка 400×800, console errors отсутствуют. Тексты черновика оставались только на fixture-странице/fixture-БД. Временная вкладка и сервер остановлены.
- Ruff check/format-check по scoped Python и explicit mypy нового контура; JavaScript syntax и scoped diff. Постоянные тестовые файлы не добавлялись.

Это самопроверка разработчика. Финальная независимая панель на совместном замороженном кандидате ЯМ+Ozon и публикация проверенной документации выполняются координаторами отдельно. Доступы настоящих кабинетов, свежесть сегодняшних counters и production не подтверждаются локальными fixtures. Ключи/реальные API/рабочая БД не использовались. Реальное платное подключение или покупка подписки не выполнялись.


Дополнительные проверки v3: реальные SQLite и PostgreSQL DTO/HTTP/cartSources 7/0/null/absent, исходная 29.10 при получении 30.10 00:30+03, ошибка day с сохранением прежнего числа/received_at/stale, strict grammar/provenance и независимая field coverage. Новый browser smoke и скачанные CSV байты сохранили эти числа за 29.10; actual shortDate helper проверен в четырёх Node TZ, включая границы недели и года. Реальное browser timezone emulation не заявляется. История старше 366 дней проверена отдельно: default 7 дней до last_available, подтверждённый пустой последний день, удалённый из каталога SKU, explicit bounded date_to, сегодняшний rank и граница 366/367 дней.

Сырые day/month/year реального API не подтверждены fixture кабинета. Адаптер поддерживает strict ISO/DD.MM.YYYY/D-DD, числовой month M/MM и strict integer year, проверяет все явные компоненты и сохраняет raw/provenance. Unknown textual month fail-closed: прошлый успех остаётся stale. Это честное ограничение совместимости, а не объявление источника недоступным. Полная спецификация поведения и источников сохранена в тематическом документе; временные материалы не являются единственным описанием ТЗ.


## Исправления второй попытки после R1

R1 завершён тремя individual defects_found. Отдельный новый coder исправил подтверждённые четыре группы в точном FIX-YM-2 scope и общий frontend quality contract для Ozon. Пригодные известные 0/0 дают ДРР 0 независимо от fullArticle; пустое пересечение и положительные расходы при нулевой базе остаются unknown. ROI/CTR не получают специальную арифметику. Качество известных частей, включая complete=true/stale=true, проходит через DTO, строки/оба периода, weighted filtered итоги и CSV. Полный SKU и WB card dedupe сохранены.

Strict_rows режим нового funnel consumer сохраняет malformed строки до Pydantic проверки, отклоняет весь mixed snapshot и сохраняет предыдущий A/B cache/last_success/received_at с новой ошибкой. Прежние report consumers сохраняют default режим. История редакций дневных заметок ЯМ отображается из revisions; notes CAS и WB/Ozon контракты сохранены. Общая таблица явно маркирует частичный сток и зависимые дни запаса; числитель сохраняет известную часть, знаменатель требует полную предыдущую календарную неделю.

Собственные проверки coder2: Python3.13.5, Node22.18.0; шесть integration методов SQLite и шесть PostgreSQL17.5 ym_coder2 (real ZIP→report limiter→job→UoW/cache preservation, strict dates/provenance, численные веса и независимое качество, notes CAS/rollback, active-user HTTP guard и GET no-write); actual Node models/renderers, scoped Ruff/format и explicit mypy. У legacy unit_economics_sync до исправления было18 ошибок strict mypy, после типизации затронутой report границы остаются14 унаследованных ошибок в других функциях; новые семь типизированных файлов проходят. Контроль не ослаблялся.

Chrome fixture проверил revisions ЯМ,24 отдельных D и реальное сохранение, filter до totals, comments autosave/409 с сохранением и явным восстановлением draft, desktop и400×800 drawer, zero/unknown/partial/stale и три actual downloaded CSV. Sales экспортирует все7дней при скрытых днях; эфемериды после скрытия ROI предыдущей недели не экспортируют это поле и его quality, сохраняя выбранную неделю. Exact Ozon DTO payload проверен общими model/renderer/CSV и browser consumers: обе недели ДРР, stale-only sales totals и zero-filter protection. WB три shared consumer страницы smoke на own fixtures; реальные WB backend/API в этом browser smoke не проверялись. Browser .waitForEvent(download) однажды не завершился, файл фактически скачался; сохранены реальные bytes по известным именам, их содержимое и SHA проверены.

Все браузерные вкладки/viewport overrides и собственные listener/PID остановлены, shared PostgreSQL cluster не тронут. Это не full R2 acceptance. Во время собственного Chrome lease exact Ozon input имел stock=null; позднее нормализованный actual DTO20/2 с подтверждённым полным спросом7дней прошёл собственный unconditional Node model/renderer/CSV probe. Аналогичный YMknown20 UI и true/false/absent flags проверены. Отдельный Ozon browserF5 проверяет его владелец; его evidence не является собственным запуском ЯМ coder. После собственного Chrome STOP исправлены explicit WB qualityExport gate и YM source-confirmation metadata; финальные callbacks/typed/HTTP/SQL проверки прошли, предыдущие browser bytes не переименовываются в свежий прогон этих source hashes. Новая независимая совместная панель и механическая публикация docs принадлежат координаторам. Live API, actual raw кабинетный формат, реальные права/подписки, production и browser timezone emulation не проверялись.


Дополнительный адресный known≠complete regression второй попытки: при одинаковых сохранённых0/0 парах удаление одного подтверждения рекламы в реальной SQLite и PostgreSQL оставляет0/weights/5usable dates, но complete=false. Заказы и реклама проверяются раздельно; при full источниках и ошибке обновления complete=true/stale=true, zero segment остаётся защищённым. Stock20/full7 demand10вдень даёт2дня известной части;6confirmed+1known-unconfirmed дают stockDays=null. WB три фактических export callbacks исполнены на одинаковом before/current input: UTF8 CSV байты равны, новые quality колонки только для numeric Ozon/ЯМ, фото/тексты исключены.


Адресное продолжение той же второй попытки до R2: по подтверждённому P3 исправлен слишком широкий alias orders, захватывавший week-YYYY-MM-DD ключи истории комментариев. Изменён только общий analyzer-model.js и cache version этого файла в трёх шаблонах. Собственный probe исполнил настоящий weeklyCommentColumns/helper/summary/metricHelp: на сохранённом v1 ошибочная метка воспроизводится, после правки шесть групп assertions проходят. day0…day6, ISO-day и точный week сохраняют order partial/stale; независимое качество комментария не блокируется. Три actual WB before/current CSV callbacks вновь дали одинаковые байты. Полные UI/PG suites не повторялись для этой alias-правки; R2 fresh panel и совместимость после внешних STOP принадлежат main. Предыдущий handoff сохранён неизменным в историческом снимке, старые доказательства не переименованы в новые.

## Передача текущей реализации по запросу пользователя

Реализация и самопроверки завершены; финальная независимая приёмка R2 не завершена и не объявляется пройденной. Первичные отчёты и уже выполненные проверки сохраняются в отдельных журналах двух направлений.

Совместный исходный кандидат: joint-r2, SHA256 ff6364a5393ef6d903752440ed352df3820b0630691e0ca97bbbe775f2c8c6ad. Все исходники продукта остаются этими проверенными байтами; при передаче опубликованы девять подготовленных документов и этот фактический итог. Журнал двух координаторов и ID запрошенных моделей сохранены в outputs текущей задачи.

По явному выбору пользователя физический переход существующей вкладки hidden→visible остаётся not_run; логика production-обработчика проверялась отдельно. Настоящие API кабинетов, права и подписки в локальных проверках не подтверждались. Непроверенное не обозначается как успешный тест. Push, релиз и деплой в этой задаче не выполнялись.
# Известные ограничения при немедленной передаче

Независимые ревью остановлены по прямому запросу пользователя 30 октября 2026 года. Полная финальная приёмка не завершена.

В первом независимом отчёте Яндекс Маркета зафиксированы следующие воспроизводимые случаи, которые не исправлялись после остановки:

- Окно почасовых коэффициентов D (общий интерфейс Ozon/ЯМ) может потерять несохранённый ввод при закрытии/повторном открытии и допускает повторное открытие во время запроса сохранения. До исправления вводите значения, нажимайте «Сохранить» и дожидайтесь завершения запроса; не закрывайте окно и не продолжайте редактирование во время сохранения.
- Агрегация сохраняет числовой результат, partial/stale и причины, но теряет expected_dates/known_dates/complete в метаданных итогов. Даты происхождения качества в агрегированных данных требуют доработки.
- У Яндекс Маркета период по умолчанию может начинаться в декабре 1999 года, если единственная подтверждённая дата — 1 января 2000 года. Обычные современные периоды этим случаем не затронуты; явная нижняя граница валидируется.

Эти находки ещё не прошли обсуждение трёх проверяющих и не являются завершённым итогом панели. Источник: отдельный immutable INITIAL Astra R2. Физическое переключение существующей вкладки hidden→visible не проверялось по согласованному с пользователем ограничению; логические обработчики проверялись отдельно. Живые API кабинетов и production не проверялись.


## Надёжность части доказательств проверки

После остановки выявлено: один тестовый harness Ozon с неверно закреплённым рабочим каталогом перезаписал семь служебных файлов результатов разработчика (fresh-bootstrap, PostgreSQL compatibility payload/results и четыре HTML-снимка). Их текущую целостность нельзя считать подтверждённой; они не служат основанием для заявления о завершённой приёмке. По известным путям записи затронуты validation outputs, не исходники продукта. Исходники при передаче совпали с зафиксированными SHA. Подробный перечень и реальные журналы сохранены в state направления Ozon; восстановление доказательств не выдумывалось.
