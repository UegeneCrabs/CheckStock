## Почему локальная загрузка ЗЦ не сохранилась

Повторное чтение `data/checkstock.db` в режиме `mode=ro` показало, что общая таблица `unit_economics_1c_source_values` теперь содержит 1559 заполненных цен, все для WB. У `303077583` в ней осталась только цена WB 848,59 ₽; записей Ozon и ЯМ уже нет. Последняя синхронизация: `2026-09-11T20:21:00.500387+00:00`.

Причина подтверждается основным кодом: `app/unit_economics_1c_source_data.py` по-прежнему выбирает только WB-каталог, а `replace_source_values` удаляет весь предыдущий снимок общей таблицы перед записью нового. Поэтому разовая загрузка исправленным скриптом не сохраняет результат, пока фоновый процесс работает со старым импортом.

В отдельной таблице `unit_economics_yandex_source_values` у этого артикула есть цена ЯМ 848,60 ₽. Текущие незавершённые изменения основного каталога добавляют её в TOTAL, но сохраняют старую группировку по штрихкоду. Их необходимо согласовать с нашей группировкой по артикулу при объединении веток.

## Основной рабочий каталог и исправленная ветка

- В основном каталоге `app/stock_total.py` группирует товары по магазину и штрихкоду, а не по артикулу между магазинами.
- В основном `app/application/stock.py` метод `register_fbs_transfer` только проверяет наличие. Списание свободного остатка, согласованное пользователем, находится в исправленной ветке.
- Основной `app/wb/api.py` всё ещё отправляет остатки FBS через `skus`; подготовленный переход на `chrtIds` находится в исправленной ветке.
- В локальной базе ещё нет таблиц `catalog_barcodes` и связей прежних артикулов. Одного копирования нового TOTAL недостаточно: нужен согласованный выпуск кода и схемы.
- Основной каталог содержит множество текущих изменений других разделов. При проверке они не перезаписывались.
