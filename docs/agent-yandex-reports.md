# Яндекс Маркет в API сотрудников

Используется существующий API `/api/agent/v1` и тот же персональный Bearer-ключ.
Передавайте `marketplace=YANDEX MARKET` (при сборке URL кодируйте пробел).
По умолчанию остаётся WB. Разрешения определяются правами сотрудника на магазин,
площадку, раздел Яндекса и действие; финансовые данные сохраняют ограничения по менеджеру.

Поддерживаются 22 метода:

- products, product-details, stocks, stock-operations;
- stock-history, orders, inbound-supplies, supply-arrivals, stock-cost-report;
- prices, costs, stock-value;
- product-newness, product-reputation, product-tags, current-economics;
- advertising, profit, target-prices, profit-calculator, economics-history.
- loss-products — убыточные товары по полному расчёту маржи за выбранный период.

Служебные stores, capabilities, article-stores и data-status учитывают Яндекс.
Каталог показывает только разрешённые области и отдельный справочник полей Яндекса.
Те же справочники включены в OpenAPI как `x-marketplace-guides`.

## Источники и ограничения

Адаптер `app/agents/yandex_reports.py` использует существующие локальные расчёты
`app/economics/yandex` и `app/yandex`. Чтение не запускает обновление площадки.
Складские методы читают общие таблицы с фильтром площадки. Расписание поступлений
остаётся общим для магазина и требует доступа ко всем его площадкам.

Prices предоставляет только текущие цены: seller_price, buyer_price, pay_price.
Даты для Яндекса отклоняются с 422. Последняя цена может быть неизвестна или устареть.
В Profit ожидаемый оборот выкупов не является фактической выручкой. При неполном
расчёте margin/roi равны null; report_margin/report_roi сохраняют значения сайта.
margin_missing_days — список дат. Пагинация применяется после фильтрации прав.
Реклама суммирует загруженные дни, а пропуски отражены в context.missing_days/complete.
История экономики — 21 день, текущий день неполный. Нулевой ответ не доказывает
отсутствие данных в маркетплейсе. API не возвращает исходные payload заказов или
служебные ссылки справочника 1С.

Отдельные сценарии profit-summary, product-analysis,
advertising-campaigns и supplies остаются WB-only. Для Яндекса доступны состав
поставок inbound-supplies и общие складские отчёты; это не эквивалент WB supplies.

## Проверка

`python -m unittest discover -s tests -q`

Тесты Яндекса проверяют отдельные права разделов и действий, изоляцию магазинов,
фильтрацию менеджеров, маршрутизацию HTTP, отсутствие полей WB в справочнике цен,
повторное использование расчётов сайта, пагинацию и сохранение неизвестных значений.
