# Выгрузка цен витрины Яндекс Маркета

Сборщик `scripts/parse_yandex_storefront_prices.py` берёт список из
`app/yandex/unit_economics_assortment.json` (155 пар магазин/артикул), находит товары в
каталоге БД, получает B2C-ссылки через официальный `offer-mappings` и последовательно
открывает их в одной вкладке с постоянным профилем браузера. Добавленные в JSON товары
попадут в следующий обход, если для магазина настроен ключ. Если выбранного товара
ещё нет в локальном каталоге, сборщик добавляет его из ответа официального API,
не заменяя существующий каталог и остатки.

Цена продавца поступает из официального `offer-prices`. Цена покупателя без Пэй —
из `collections.offerAnalytics[*].prices.price.value`. Проверяются businessId и ID
карточки, либо SKU, если oskuId отсутствует. Цена другого продавца, зелёная цена Пэй,
зачёркнутая цена и цена без НДС не используются как замена.
Цена относится к региону и сессии сборщика. В проверке Маркет показывал регион Москва
без входа в аккаунт; персональная цена в другом браузере может отличаться.

Результат каждой карточки сразу записывается в `yandex_storefront_prices` той же БД,
которую использует сайт. Калькулятор ЯМ показывает цену продавца и покупателя, время
обновления и причину отсутствия цены. При ошибке последняя удачная цена сохраняется
для диагностики, но не выдаётся за текущую. Днём срок актуальности — два часа;
при плановой ночной паузе он продлевается до часа после следующего запуска.
Расчёт маржи и ROI этим сборщиком не добавляется.

## Windows / PyCharm

Команды выполняются из корня проекта, в имени файла обычные подчёркивания без `\`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-parser.txt
.\.venv\Scripts\python.exe .\scripts\parse_yandex_storefront_prices.py --force
```

Нужен установленный Google Chrome. Для постоянной работы в том же браузере:

```powershell
.\.venv\Scripts\python.exe .\scripts\parse_yandex_storefront_prices.py --loop
```

`--loop` проверяет включённые магазины ежедневно в **01:00** и каждый час
с **08:00 до 19:00 включительно**, по **Asia/Yekaterinburg (UTC+5)**: 13 запусков
в сутки, включая выходные. Время привязано к началу часа и не зависит от часового
пояса сервера или времени предыдущей проверки. После запуска/перезапуска процесс
ждёт ближайшего времени по расписанию; немедленный обход доступен через `--force`.
Если обход затянулся или компьютер спал, пропущенные запуски не накапливаются:
следующий обход начинается в ближайшее разрешённое время. Параллельные обходы
блокируются общей блокировкой БД и блокировкой профиля. Настройка магазина
«Цены витрины Яндекс Маркета» на странице интеграций управляет участием в автоматическом
обходе. Разовый запуск проверяет весь список независимо от этих выключателей.
После остановки процесса или выключения компьютера выгрузка прекращается.

Для локального автозапуска настроена задача Windows `CheckStock-YandexStorefront-Hourly`:
она запускает `.venv\Scripts\pythonw.exe` с `--loop` при входе пользователя. Расписание
01:00 и 08:00–19:00 соблюдает сам сборщик. Браузер открывается в интерактивной сессии Windows,
журнал пишется в `data/yandex-storefront/live-check/worker.log` (с ротацией).
На сервере вместо задачи Windows используется контейнер ниже.

Управление уже установленной локальной задачей (PowerShell):

```powershell
Get-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
Stop-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
Disable-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
# Включить обратно
Enable-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
Start-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
```

При принудительной остановке блокировка БД истекает максимум через 10 минут.
Для разового ручного запуска на той же машине сначала остановите задачу, чтобы
не создавать конкурирующие браузеры.

Дополнительные режимы:

```powershell
# Проверить один товар из списка
.\.venv\Scripts\python.exe .\scripts\parse_yandex_storefront_prices.py --article tris:153985484
# Повторить только ошибки; уже полученные цены и подтверждённое отсутствие пропускаются
.\.venv\Scripts\python.exe .\scripts\parse_yandex_storefront_prices.py --retry-failed
# Проверить сопоставление с БД и API без браузера (цены продавца сохраняются)
.\.venv\Scripts\python.exe .\scripts\parse_yandex_storefront_prices.py --prepare-only
```

Для сохранения сессии всегда используйте один `--state-dir`; по умолчанию это
`data/yandex-storefront`. Профиль, `latest.json`, HTML и скриншот ошибки находятся там
и исключены из Git. В текущей проверке использован `data/yandex-storefront/live-check`.
Эта диагностика может содержать данные сессии; её не следует публиковать.

## CAPTCHA

Ключ 2Captcha хранится в локальном `secrets/captcha.json`:

```json
{"api_key": "ВАШ_КЛЮЧ"}
```

Также поддерживаются `CHECKSTOCK_CAPTCHA_KEY_PATH` и `CHECKSTOCK_CAPTCHA_API_KEY`.
Ключ и ответы не печатаются. Сначала нажимается «Я не робот». При появлении известного
графического задания отправляются только изображение и порядок фигур. Текстовая
капча поддерживается отдельно; неизвестный вариант останавливает обход и сохраняет
диагностику. Максимум две попытки на проверку и десять платных задач за обход
(`--max-captchas`). При неопределённом ответе создания задачи повторная задача
автоматически не создаётся. В отчёт записываются число отправок и стоимость готовых
ответов; итоговое списание проверяйте в кабинете 2Captcha.

`--inspect` сохраняет страницу после проверки и не создаёт платных задач.
Решение CAPTCHA может быть отклонено Маркетом; работа без остановок не гарантируется.
При HTTP 403/429 или непройденной проверке обход прекращается, следующий автоматический
запуск — в ближайшее разрешённое время по расписанию. Проверка на Windows проводилась с видимым Chrome:
headless-вариант при проверке получал HTTP 403.

## Linux-сервер с существующим Docker Compose

На сервере должны быть этот код, ключи магазинов в `secrets/yandex_tokens.json`, ключ
2Captcha в `secrets/captcha.json` и доступ контейнерного пользователя UID 10001 на
чтение этих файлов. Ключи не входят в образ. Не переносите личный профиль Chrome:
сборщик создаёт собственный постоянный профиль в отдельном Docker volume.

```bash
# Обновить приложение, чтобы оно показывало новые поля, и запустить сборщик
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml up -d --build app yandex-parser
# Проверить журнал
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml logs --tail=100 -f yandex-parser
```

Для полного обхода сразу после установки остановите автоматический контейнер,
выполните разовый запуск и затем верните расписание:

```bash
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml stop yandex-parser
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml run --rm --no-deps yandex-parser xvfb-run -a python -u scripts/parse_yandex_storefront_prices.py --force
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml up -d yandex-parser
```

Проверьте итоговый отчёт: `selected: 155`, `checked`, `statuses` и `skipped`.
Для магазина без ключа или товара без карточки цена останется отсутствующей;
причина будет записана в БД и журнал. Полный список включает 29 товаров Sokoloff:
для их проверки нужен настроенный ключ этого магазина.

Сборщик использует ту же PostgreSQL, что и `app`, и запускает обычный Chromium под
Xvfb без публичного порта браузера. Работает от непривилегированного пользователя с
sandbox и профилем seccomp Playwright; перезапускается средствами Docker. Windows
вариант проверен живым обходом; сборка и запуск Linux-контейнера требуют проверки
на целевом сервере (в текущем окружении Docker отсутствует).

Веб-приложение не запускает второй браузер через `app/background.py`: автоматический
обход выполняет отдельный процесс/контейнер. Статус и следующий запуск записываются
в существующий журнал фоновых загрузок сайта.
