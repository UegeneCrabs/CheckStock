# Выгрузка цен витрины Яндекс Маркета

Сборщик `scripts/parsers/parse_yandex_storefront_prices.py` берёт список из
`app/yandex/unit_economics_assortment.json` (155 пар магазин/артикул), находит товары в
каталоге БД, получает B2C-ссылки через официальный `offer-mappings` и последовательно
открывает их в одной вкладке с постоянным профилем браузера. Добавленные в JSON товары
попадут в следующий обход, если для магазина настроен ключ. Если выбранного товара
ещё нет в локальном каталоге, сборщик добавляет его из ответа официального API,
не заменяя существующий каталог и остатки.

Цена продавца поступает из официального `offer-prices`. Цена покупателя без Пэй —
из `collections.offerAnalytics[*].prices.price.value`. Проверяются businessId и ID
карточки, либо SKU, если oskuId отсутствует. Цена другого продавца, зелёная цена Пэй,
зачёркнутая цена и цена без НДС не используются как замена.
Цена относится к региону и сессии сборщика. В проверке Маркет показывал регион Москва
без входа в аккаунт; персональная цена в другом браузере может отличаться.

Результат каждой карточки сразу записывается в `yandex_storefront_prices` той же БД,
которую использует сайт. Калькулятор ЯМ показывает цену продавца и покупателя, время
обновления и причину отсутствия цены. При ошибке последняя удачная цена сохраняется
для диагностики, но не выдаётся за текущую. Днём срок актуальности — два часа;
при плановой ночной паузе он продлевается до часа после следующего запуска.
Расчёт маржи и ROI этим сборщиком не добавляется.

## Windows / PyCharm

Команды выполняются из корня проекта, в имени файла обычные подчёркивания без `\`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-parser.txt
.\.venv\Scripts\python.exe .\scripts\parsers\parse_yandex_storefront_prices.py --force
```

Нужен установленный Google Chrome. Для работы по расписанию с постоянным профилем:

```powershell
.\.venv\Scripts\python.exe .\scripts\parsers\parse_yandex_storefront_prices.py --loop
```

`--loop` проверяет включённые магазины ежедневно в **01:00** и каждый час
с **08:00 до 19:00 включительно**, по **Europe/Moscow (UTC+3)**: 13 запусков
в сутки, включая выходные. Время привязано к началу часа и не зависит от часового
пояса сервера или времени предыдущей проверки. После запуска/перезапуска процесс
ждёт ближайшего времени по расписанию; немедленный обход доступен через `--force`.
Если обход затянулся или компьютер спал, пропущенные запуски не накапливаются:
следующий обход начинается в ближайшее разрешённое время. Параллельные обходы
блокируются общей блокировкой БД и блокировкой профиля. Настройка магазина
«Цены витрины Яндекс Маркета» на странице интеграций управляет участием в автоматическом
обходе. Разовый запуск проверяет весь список независимо от этих выключателей.
После остановки процесса или выключения компьютера выгрузка прекращается.

Для локального автозапуска настроена задача Windows `CheckStock-YandexStorefront-Hourly`:
она запускает `.venv\Scripts\pythonw.exe` с
`-u -m scripts.parsers.parse_yandex_storefront_prices --loop` из корня проекта
при входе пользователя. Старый путь `scripts/parse_yandex_storefront_prices.py`
после переноса скрипта больше не существует; его нужно заменить в действии задачи.
Расписание
01:00 и 08:00–19:00 по Москве соблюдает сам сборщик. Браузер открывается в интерактивной сессии Windows,
журнал пишется в `data/yandex-storefront/live-check/worker.log` (с ротацией).
На сервере вместо задачи Windows используется контейнер ниже.

Управление уже установленной локальной задачей (PowerShell):

```powershell
Get-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
Stop-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
Disable-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
# Включить обратно
Enable-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
Start-ScheduledTask -TaskName CheckStock-YandexStorefront-Hourly
```

При принудительной остановке блокировка БД истекает максимум через 10 минут.
Между обходами браузер закрыт, поэтому останавливать задачу для ручной кнопки
не требуется; одновременные обходы блокируются.

Дополнительные режимы:

```powershell
# Проверить один товар из списка
.\.venv\Scripts\python.exe .\scripts\parsers\parse_yandex_storefront_prices.py --article tris:153985484
# Повторить только ошибки; уже полученные цены и подтверждённое отсутствие пропускаются
.\.venv\Scripts\python.exe .\scripts\parsers\parse_yandex_storefront_prices.py --retry-failed
# Проверить сопоставление с БД и API без браузера (цены продавца сохраняются)
.\.venv\Scripts\python.exe .\scripts\parsers\parse_yandex_storefront_prices.py --prepare-only
```

Для сохранения сессии всегда используйте один `--state-dir`; по умолчанию это
`data/yandex-storefront/live-check` в Windows и `data/yandex-storefront` в Linux.
Профиль, `latest.json`, HTML и скриншот ошибки находятся там и исключены из Git.
Эта диагностика может содержать данные сессии; её не следует публиковать.

## Прокси магазинов

Необязательный файл `secrets/yandex_storefront_proxies.json` задаёт постоянный
HTTP(S)-прокси с авторизацией для каждого магазина. Образец на семь магазинов:
`secrets/example/yandex_storefront_proxies.example.json`.
Заполните `server` (например, `http://proxy.example:3128`), `username`, `password`
для магазинов и установите верхнее поле `enabled` в `true`. Логин и пароль
указываются отдельно от адреса. SOCKS-прокси с логином и паролем этим вариантом
не поддерживаются; нужен HTTP(S)-порт провайдера.

Рабочий файл исключён из Git и не копируется в Docker-образ. Оба контейнера уже
читают каталог `secrets` через общий mount. Нестандартный путь задаётся переменной
`CHECKSTOCK_YANDEX_STOREFRONT_PROXIES_PATH` в обоих процессах. Файл перечитывается
перед каждым обходом. Отсутствие файла по умолчанию или `enabled: false` сохраняет
прямое подключение; явно указанный отсутствующий файл считается ошибкой.

При включённом режиме прокси профиль каждого магазина хранится в
`<state-dir>/stores/<магазин>/browser-profile`. Кнопка, CLI и расписание используют
одни настройки. Одновременно открыт один браузер; при смене магазина он закрывается.
Прокси используются только для витрины, официальный API и сервис CAPTCHA продолжают
работать через обычное подключение. Общий лимит CAPTCHA на обход сохраняется.

Если у магазина не задан прокси или соединение через него не удалось, в результате
будет `proxy_error`; запросы магазина не перенаправляются на сервер или чужой прокси.
При временной сетевой ошибке, ошибке авторизации или создания туннеля браузер
один раз для текущего товара повторяет запрос в новой вкладке с тем же прокси
и учётными данными. Это учитывает
сбой первого запроса на сохранённом профиле Chrome. Стартовые вкладки закрываются;
новая вкладка создаётся после настройки контекста браузера. HTTP 403/429 таким
способом не повторяются.
Только подтверждённая ошибка прокси после повтора прекращает обращения по остальным
товарам магазина в этом обходе. Ошибка отдельной страницы (например, `ERR_ABORTED`
или `ERR_CONNECTION_RESET`) не отключает магазин. Код сетевой ошибки сохраняется
в сообщении товара и журнале; адреса и пароли из исключений браузера не выводятся.
HTTP 403/429 и непройденная CAPTCHA по-прежнему останавливают текущий обход.
Настройка нескольких прокси не увеличивает частоту обхода и не меняет расчёт цен.

## CAPTCHA

Ключ 2Captcha хранится в локальном `secrets/captcha.json`:

```json
{"api_key": "ВАШ_КЛЮЧ"}
```

Также поддерживаются `CHECKSTOCK_CAPTCHA_KEY_PATH` и `CHECKSTOCK_CAPTCHA_API_KEY`.
Ключ и ответы не печатаются. Сначала нажимается «Я не робот». После нажатия сборщик
до 20 секунд ожидает перехода на карточку или загрузки изображения задания;
исчезновение кнопки само по себе не означает неизвестный вариант CAPTCHA.
При появлении известного
графического задания отправляются только изображение и порядок фигур. Текстовая
капча поддерживается отдельно; неизвестный вариант останавливает обход и сохраняет
диагностику. Максимум две попытки на проверку и десять платных задач за обход
(`--max-captchas`). При неопределённом ответе создания задачи повторная задача
автоматически не создаётся. В отчёт записываются число отправок и стоимость готовых
ответов; итоговое списание проверяйте в кабинете 2Captcha.

`--inspect` сохраняет страницу после проверки и не создаёт платных задач.
Решение CAPTCHA может быть отклонено Маркетом; работа без остановок не гарантируется.
При HTTP 403/429 или непройденной проверке текущий обход прекращается.
Локальные паузы на 6 часов и на час отключены; старые искусственные сроки
повторный запуск не блокируют. Учитывается только явный `Retry-After` от сервера,
сохранённый в БД как `server_retry_after`. Он действует для кнопки, CLI и расписания,
в том числе после перезапуска. Если сервер указал такой срок, следующий
автоматический обход — ближайшее время расписания после окончания паузы.
`--force` и смена профиля паузу не обходят; `--prepare-only` может обновить данные API.
Эта пауза не означает, что Яндекс снимет блокировку к указанному времени; при
сохранении запрета нужен разбор с поддержкой Яндекса.

Между карточками — не менее 5 секунд. Браузер открывается на один обход и затем
закрывается, сохраняя профиль. Между обходами профиль свободен для ручной кнопки.
В Windows общий путь по умолчанию `data/yandex-storefront/live-check`, в Linux —
`data/yandex-storefront`; свой путь задаётся одинаковой переменной
`CHECKSTOCK_YANDEX_STOREFRONT_STATE_DIR` для обоих процессов.
Кнопка и расписание вызывают один `run_browser_once`, без принудительного headless. Проверка на Windows проводилась с видимым Chrome:
headless-вариант при проверке получал HTTP 403.

## Linux-сервер с существующим Docker Compose

На сервере должны быть этот код, ключи магазинов в `secrets/yandex_tokens.json`, ключ
2Captcha в `secrets/captcha.json` и доступ контейнерного пользователя UID 10001 на
чтение этих файлов (оба контейнера используют UID 10001). Ключи не входят в образ. Не переносите личный профиль Chrome:
сборщик создаёт собственный постоянный профиль в общем Docker volume `yandex-parser-data` для приложения и сборщика.

```bash
# Обновить приложение, чтобы оно показывало новые поля, и запустить сборщик
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml up -d --build app yandex-parser
# Проверить журнал
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml logs --tail=100 -f yandex-parser
```

Для полного обхода сразу после установки остановите автоматический контейнер,
выполните разовый запуск и затем верните расписание:

```bash
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml stop yandex-parser
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml run --rm --no-deps yandex-parser xvfb-run -a python -u scripts/parsers/parse_yandex_storefront_prices.py --force
docker compose -f docker-compose.yml -f docker-compose.yandex-parser.yml up -d yandex-parser
```

Проверьте итоговый отчёт: `selected`, `checked`, `statuses` и `skipped`.
Для магазина без ключа или товара без карточки цена останется отсутствующей;
причина будет записана в БД и журнал. Количество выбранных товаров зависит
от актуального ассортимента и включённых магазинов.

Сборщик использует ту же PostgreSQL, что и `app`, и запускает обычный Chromium под
Xvfb без публичного порта браузера. Работает от непривилегированного пользователя с
sandbox и профилем seccomp Playwright; перезапускается средствами Docker.
При обновлении проверяйте запуск браузера в обоих контейнерах и доступ к общему
профилю и ключам до включения автоматического обхода.

Веб-приложение не запускает второй браузер через `app/jobs/background.py`: автоматический
обход выполняет отдельный процесс/контейнер. Статус и следующий запуск записываются
в существующий журнал фоновых загрузок сайта.
