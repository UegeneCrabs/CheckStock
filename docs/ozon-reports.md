# Юниточная прибыль и целевая цена Ozon

Два отчёта доступны из меню «Отчёты» при включённом preview экономики Ozon:

- `/sales/unit-economics-1c/ozon/reports/unit-profit`;
- `/sales/unit-economics-1c/ozon/reports/target-price`.

Интерфейс использует общие таблицы, фильтры и редактор целей Яндекс Маркета.
Расчёты, данные и сохранения ограничены площадкой Ozon и доступными пользователю
кабинетами. Открытие и формирование отчётов не обращается к внешнему API.

## Юниточная прибыль

Пользователь выбирает даты, магазины, категории, менеджеров и товары. Доступны
группировка по категориям, показатели по дням и XLSX. Период ограничен общим
`WEB.report_max_days`; будущие даты отклоняются. При подробном просмотре товаров
применяется серверная пагинация, XLSX содержит всю выбранную выборку.

Включаются товары с положительным историческим остатком, заказами или рекламой
за период; если период содержит сегодня, учитывается и текущий остаток. Продажи,
отмены и ТО берутся из дневных строк FBO/FBS. Подтверждённый день без заказов
даёт ноль, неизвестный день остаётся неизвестным.

Прибыль и ROI используют `economics_7d` с выбранным диапазоном, несмотря на
историческое имя поля. Прибыль периода — сумма сохранённых дневных прибылей,
ROI — прибыль / соответствующая закупочная база × 100. Текущие цены и затраты
не подставляются задним числом. Детализация раскрывает сохранённую цену,
закупку, ФФ, комиссию, логистику, хранение, рекламу, эквайринг и налоги.
[Правила полноты и формула](ozon-margin.md) совпадают с таблицей экономики.

ДРР рассчитывается по совпадающим доступным датам рекламы и ТО с учётом
эффективного выкупа: реклама / (ТО после отмен × выкуп / 100) × 100.
В общих итогах используются соответствующие числитель и знаменатель;
неизвестные значения не превращаются в нули. Средний выкуп взвешивается
только по товарам с известным выкупом. CPC использует расходы на клики.
Неполные расчёты сохраняются с указанием дат и причин; XLSX содержит отдельный
лист дневных расчётов, признаки полноты и диагностические коды.

Остатки и запас в днях отражают текущее состояние, а не остаток на последнюю
дату выбранного периода. История остатков используется для отбора товаров.

## Целевая цена и ROI

Отчёт включает товары с текущим остатком FBO/FBS/ФФ, поставкой в пути либо ТО
за последние семь завершённых дней по Москве. Текущий ROI рассчитывается
по тем же значениям, что и калькулятор: текущие цены и расходы, недельная
реклама на ожидаемый выкуп. Текущий ДРР использует совпадающие даты ТО и рекламы.

Рекомендация подбирает цену продавца в копейках и возвращает также цену с СПП,
цену с Кошельком и фактический ROI после округления. Каждый шаг проверяется
существующим `ozon_calculator.recalculate`. Плановая реклама на выкупленную
штуку = новая цена продавца × целевой ДРР / 100.

В сценарии сохраняются текущие доли СПП и Кошелька, текущая ставка комиссии
(сумма комиссии / исходная цена продавца), логистика, хранение и остальные
расходы. Изменение тарифа комиссии Ozon при переходе в другой ценовой диапазон
не прогнозируется. При недостатке параметров, несогласованных ценах,
неположительной закупке или недостижимой цели до 1 млрд рублей рекомендации
нет; интерфейс показывает причину. Частичная недельная история отмечается
отдельно, даже если плановый сценарий можно рассчитать.

«Настройка ROI» редактирует цели выбранного кабинета: общий ROI, значения для
A/B/C/D/F/NEW/U и общий ДРР. Это те же настройки, что в параметрах кабинетов.
Пустое поле кода наследует общий ROI, ноль — самостоятельная цель. Приоритет:
индивидуальная цель товара → цель кода → общая цель кабинета.

Нажатие на товар открывает сценарий с индивидуальными целями и исходными
расходами. Предпросмотр не сохраняет сценарий. «Сохранить цели» сохраняет
только ROI/ДРР товара, «Сбросить цели» возвращает наследование кабинета.
Ни одна из этих операций не меняет цену в Ozon.

Цели хранятся в существующих таблицах `ozon_cabinet_settings` и
`unit_economics_1c_product_settings` с `marketplace=OZON`; миграция не требуется.
Кабинет защищён числовой ревизией, товар — непрозрачным `updated_at`.
Конкурирующее сохранение получает 409; ревизию нельзя интерпретировать
или передавать в URL без кодирования.

## Контракты и модули

API имеет префикс `/api/unit-economics-1c/ozon/reports`:

| Метод и путь | Контракт |
|---|---|
| `GET /unit-profit` | `OzonProfitQuery` → `OzonProfitReport` |
| `GET /unit-profit/filters` | Доступный каталог категорий, менеджеров и товаров |
| `GET /target-price` | `store`, `article` → `OzonTargetReport` |
| `POST /target-price/{store}/preview` | `OzonTargetPreview` → пересчитанный отчёт |
| `PUT /target-price/{store}/targets` | `OzonTargetChange` → `OzonTargetRecord` |
| `DELETE /target-price/{store}/targets` | `article`, `revision` → сброс индивидуальных целей |
| `GET/PUT /target-price/settings/{store}` | Цели кабинета и числовая ревизия; расходы и выкуп сохраняются |
| `POST /target-price.xlsx` | Выбранные идентификаторы; значения пересчитываются сервером |

XLSX прибыли находится по пути страницы с суффиксом `/unit-profit.xlsx`.
Проверка доступа выполняется сервером для каждого кабинета; неизвестный кабинет
даёт 403, отсутствующий товар — 404, неверные параметры — 422.

Основные модули: `app/dto/ozon_reports.py`,
`app/application/ozon_reports.py`, `app/infrastructure/ozon_reports_repository.py`,
`app/economics/{ozon_reports,ozon_target_prices}.py`,
`app/web/routers/ozon_reports.py`, `app/infrastructure/ozon_report_export.py`.
Разметка и подписи находятся в `templates/economics/ozon/`,
`static/economics/ozon/reports.js` и `report-columns.json`. Общие компоненты
WB/ЯМ выбирают поведение Ozon по явной конфигурации площадки.

Проверка 29.10.2026: временные расчётные и интеграционные сценарии на SQLite
и PostgreSQL, HTTP-контракты, сохранение и конфликт ревизий, XLSX, Ruff, mypy,
проверки JavaScript и локальный браузер на синтетической выборке. Проверочные
сервисы и временные сценарии удаляются после завершения задачи.
