# API аналитики CheckStock

API расположен под `/api/agent/v1`. Личный Bearer-ключ связан с существующим пользователем CheckStock. При каждом запросе проверяются срок действия ключа и активность его владельца. Все активные пользователи видят настроенные магазины и реализованные отчёты; автоматического ограничения по ФИО менеджера нет. Подробности — в [контракте учётных записей](authentication.md).

## Подключение

Страница `/ai-agents` содержит управление ключами, схему API и готовую инструкцию подключения. Текст инструкции хранится в `static/agents/agent-instructions.txt`, а схема формируется приложением по адресу `/api/agent/v1/openapi.json`.

Для внешнего подключения задайте `CHECKSTOCK_AGENT_PUBLIC_URL` — публичный HTTPS-адрес приложения. Развёртывание описано в [agent-api-deployment.md](agent-api-deployment.md).

## Доступные отчёты

Сначала получите `capabilities`, `stores` и `data-status`: они определяют доступные пользователю магазины, площадки, отчёты и состояние данных. Параметры конкретного отчёта смотрите в актуальной схеме API.

| Метод GET | Содержание |
|---|---|
| `products`, `product-details` | Каталог, поиск и карточка товара. |
| `product-newness`, `product-reputation`, `product-tags` | Новизна, отзывы и классификация товаров. |
| `advertising` | Реклама и её показатели. |
| `stocks`, `stock-value` | Текущие остатки и стоимость по известной ЗЦ. |
| `stock-operations`, `supplies` | Складские операции и планы поставок. |
| `prices`, `costs` | Цены, себестоимость и расходы. |
| `profit`, `loss-products` | Показатели отчёта прибыли и товары с убытком. |
| `profit-calculator` | Сохранённые входные данные и результаты калькулятора. |
| `current-economics` | Текущая экономика из таблицы сайта. |
| `target-prices` | Целевые цены и предупреждения исходных расчётов. |

`article-stores` помогает определить доступный магазин по артикулу. Поддержку площадок проверяйте через `capabilities`; она различается между отчётами.

Наличие крайних дат в `data-status` не доказывает полноту периода. Пропущенные значения, неполные расчёты и предупреждения источника должны сохраняться в ответе пользователю. Отчёт прибыли, текущая экономика и калькулятор имеют разные источники и периоды; их показатели нельзя автоматически подменять друг другом.

Отчёты читают доступные снимки и данные приложения. Получение отчёта не является разрешением изменять остатки, заказы, цены или права пользователя.

## Ключи из командной строки

Из корня проекта на нужной машине:

```shell
python -m scripts.ops.agent_key issue --user-id 7 --days 30 --output secrets/employee-7-key.txt
python -m scripts.ops.agent_key list
python -m scripts.ops.agent_key revoke ID_КЛЮЧА
```

Файл нового ключа предназначен только его владельцу. В хранилище приложения сохраняется хеш. Отзыв ключа и отключение пользователя прекращают доступ; все активные пользователи имеют одинаковую видимость данных.


## Общая инструкция ИИ-агентов

Вкладка `/ai-agents/instructions` и блок на `/ai-agents/gpt` показывают один файл
`static/agents/agent-instructions.txt`. Страницы используют общий шаблон
`agents/instruction-card.html`; загрузка без кеша и обе кнопки копирования GPT
обслуживаются `static/agents/instructions.js`. Копируется тот же текст, который
виден на странице. При ошибке загрузки кнопки недоступны. Общий
`static/agents/clipboard.js` сохраняет резервное копирование через выделение текста,
в том числе для ключей и схемы. Навигация вкладок — `agents/navigation.html`.

MCP читает тот же файл в `analyst_instructions()` при `initialize` и через
`getAnalyticsInstructions`, адаптируя формулировки авторизации и добавляя правила MCP.
Это общая базовая инструкция, а не обещание побайтового равенства всего ответа MCP.
В уже созданном GPT инструкцию и схему нужно обновить вручную после выкладки.
Лимит текста GPT проверяется с учётом UTF-16 и переводов строк CRLF.

Контракт новых методов СПП: [почасовая и дневная история](agent-spp-history.md).
Проверки интерфейса: `node --test tests/agent_instructions.cjs` и
`python -m unittest discover -s tests -p test_agent_instruction_pages.py -v`.

### Термины в общей инструкции ИИ

«Стандартные условия» означают сценарий без ИУ; ИУ — индивидуальные условия, также «специальные условия», «спецусловия» и «спец условия». Запросы комиссий, логистики и прибыли на стандартных условиях нельзя подменять данными с ИУ. Метод StandardCosts возвращает прибыль/ROI и состояние; недоступные через API статьи расходов агент должен обозначать как ограничение.

Слова «прибыль», «чистая прибыль», «маржа», «ROI» и «РОИ» в запросах команды относятся к расчётным показателям сайта. В ответах прибыль называется расчётной (потенциальной), ROI — расчётным. Сайт не подтверждает фактическую чистую прибыль. Само употребление этих синонимов не требует уточнения.

Правила хранятся в `static/agents/agent-instructions.txt`: вкладка инструкции и копирование для GPT используют этот файл, MCP передаёт его при инициализации и через getAnalyticsInstructions. В существующем GPT с Actions инструкцию необходимо скопировать заново.

### Сохранение правил при сокращении инструкции

Общая инструкция сохраняет правила новинок: подтверждённое отсутствие поступления и остатка означает «Ожидает поступления», а неизвестный остаток не равен нулю. Дата запуска не выводится из sales_days. Анализ включает этапы первого дня, дней 2–4 и первых 14 дней, обоснование уровней риска и ограничение: наличие на ФФ не доказывает доступность FBO/FBS.

Чтобы сохранить лимит поля GPT, перечисления полей сокращены в пользу схемы инструментов. Правила СПП, стандартных/индивидуальных условий и потенциальной прибыли сохранены. Проверка сравнивает всю базовую инструкцию с передачей через MCP с учётом адаптации авторизации; это не проверка поведения самой модели.
