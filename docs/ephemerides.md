# Эфемериды WB

Раздел **Аналитика → Эфемериды**: `/analytics/ephemerides`. История комментариев:
`/analytics/ephemerides/comments`. Используется оформление анализатора и расположение
блоков из HTML-макета: сводка магазинов, реквизиты, остатки, контроль, предыдущая и
выбранная недели, недельные комментарии. Поставщик удалён, категория одна.
Заголовки, итоги и ячейки используют общую палитру анализатора: реквизиты — сиреневые,
остатки — голубые, контроль — жёлтый, предыдущая неделя — сине-фиолетовая,
выбранная — зелёная, комментарии — бежевые. При наведении цвет блока сохраняется.
После успешной загрузки основная страница не показывает информационную надпись
о дате сохранённых данных; сообщения загрузки и ошибок остаются в строке состояния.
Статус сохранения комментариев и кнопка повторного сохранения находятся рядом
с заголовком «Эфемериды WB». Пустая строка загрузки не занимает место.
Поиск и переключатели «Все товары», «Ниже цели», «ROI < 0» расположены слева
в одном ряду у нижнего края верхнего блока, ближе к основной таблице; если места
мало, переключатели переносятся под поиск.
Сводка магазинов прижата к правому краю. Переключатель находится в заголовке
столбца «Магазин»: в свёрнутом виде показывается одна строка «Все магазины»,
в развёрнутом — отдельная строка каждого магазина. Общий итог учитывает фильтры
основной таблицы, не дублирует показатели артикула по размерам, а процент отклонения
рассчитывает от общих сумм. Состояние хранится в настройках вида в localStorage.
При сворачивании освобождается место для основной таблицы. На узком экране сводка
переходит под них. «История комментариев» и «Экспорт» находятся в панели основной
таблицы рядом с выбором недели и колонок. Кнопка «Все поля» сразу возвращает
таблицу к самому левому краю. Остальные кнопки совмещают начало выбранного блока
с правой границей закреплённого столбца «Товар» по фактическому положению ячеек,
чтобы первые столбцы блока не скрывались при переходе.
Шапка таблицы компактная: группы — 24 px, названия столбцов — от 56 px, итоги — 24 px.
Она закрепляется при вертикальной прокрутке целиком, поэтому переносы названий
не приводят к наложению строк и визуальному сужению итогов.
Фильтры столбцов используют общий компонент юнит-экономики WB/ЯМ
`CheckStockTableFilter`: компактное меню рядом с кнопкой в шапке, сортировка,
поиск значений, «Выбрать все», «Сбросить», «Отмена» и «OK». Отдельного модального
окна нет. Список значений берётся из всех товаров, подходящих под поиск и сегмент,
а не только с текущей страницы. Отбор применяется до пагинации и пересчёта итогов;
он сохраняет привязку к столбцу при скрытии групп и переключении вида товара.
Нажатие вне меню, Escape и прокрутка таблицы закрывают меню без применения.

## Периоды и источники

- Неделя ISO, понедельник–воскресенье; дата «сегодня» определяется по Москве.
  Факт заказов текущей недели учитывает только завершённые дни. Остальные
  недельные показатели по-прежнему могут включать сегодняшние наблюдения.
- По умолчанию товары ранжируются по **ТО за сегодня**, по убыванию, независимо
  от выбранной недели. Столбец «ТО сегодня, ₽» находится в реквизитах товара;
  неизвестный ТО идёт после известных значений, включая подтверждённый ноль.
  Ручная сортировка по другим столбцам доступна; сброс возвращает сегодняшний ТО.
- **ТО эфемериды по цели, ₽** — `Цель недели, шт × Цена поставщика, ₽`
  соответствующей недели. Сервер передаёт результат в `previous.turnover` и
  `current.turnover`; основная таблица показывает выбранную неделю, карточка — обе.
  Расчёт не зависит от заказов и полноты воронки продаж. Если цель или цена
  неизвестны, результат — `null` (в интерфейсе `—`); известный ноль сохраняется.
  Итог суммирует рассчитанные значения всех отобранных строк, включая размеры;
  экспорт и сортировка используют то же значение.
- Факт завершённой недели в штуках — заказы минус отмены. В текущей неделе
  показываются заказы с понедельника по вчера. В понедельник до завершения первого
  дня факт неизвестен. При положительной цели красный означает факт ниже цели,
  зелёный — от цели до превышения менее чем на 20%, оранжевый — превышение на 20%
  и больше. Факт берётся через `load_product_metrics`,
  включая периодный снимок при полном совпадении дат. При неполном покрытии
  учитываются только подтверждённые дни; данные РНП не подставляются.
- В блоке выбранной недели «Тренд продаж за 3 дня, шт» показывает заказы минус
  отмены по трём завершённым дням, от раннего к позднему. Для текущей недели
  последний день — вчера по Москве, для завершённой — воскресенье этой недели.
  Подсказка и CSV указывают даты. Итог считает каждый nmID один раз на магазин
  для каждой даты, а сортировка сравнивает последний показатель с первым.
- Сводка магазинов наверху показывает выбранную неделю. Цель — сумма «ТО эфемериды
  по цели» по отобранным товарам. Факт — валовая сумма заказов WB с понедельника
  по сегодня для текущей недели или по воскресенье для завершённой. Известная
  часть суммы при пропусках отмечается звёздочкой.
- Прогноз текущей недели — средний дневной ТО с понедельника по сегодня,
  умноженный на семь. Для завершённых дней используется факт, для сегодняшнего —
  `ТО сегодня × D` по [почасовому коэффициенту кабинета](wb-cabinet-settings.md).
  При пропусках среди прошедших дней или отсутствии прогноза на сегодня недельный
  прогноз не рассчитывается. Для завершённой недели в столбце прогноза
  используется полный факт недели. Разница и отклонение сравнивают прогноз
  или итог с недельной целью.
- ROI, ДРР, CTR и полнота источников используют правила `app/analytics/analyzer.py`.
  CTR считается отношением суммы кликов к сумме показов; ДРР — рекламных расходов
  к ожидаемой сумме выкупа за совпадающие дни. ROI — из дневных снимков экономики.
- Цены, СПП, кошелёк — последний сохранённый снимок **внутри соответствующей
  недели**, без подстановки сегодняшней цены за прошлую неделю.
- Исходный план текущей недели берётся из справочника 1С, прошлой — из последнего
  сохранённого за ту неделю значения `source.raw.reference.goal_week` в `economics_daily`.
  Старые снимки без этого поля остаются без плана; история не восстанавливается
  сегодняшними данными. Этот план показан в штуках и доступен для чтения.
- Менеджер, категория, проект, ABC-D — справочники/каталог БД; рейтинг — текущее
  сохранённое значение. Сток берётся из отдельного снимка выбранной недели.
- **На ФФ** — сумма `ff_stock.quantity` по всем фулфилментам для точного артикула
  (включая размер), магазина и площадки `WB`. Используется `ff_available` из
  `get_stock_items(store, "WB")`; остатки других магазинов и площадок не входят.
  Ноль в новом снимке означает отсутствие остатков ФФ: нулевые строки `ff_stock`
  удаляются складскими операциями. Поле JSON — `ff`.
- **Сток, доступный к продаже** (`stock`) — сумма FBO и FBS из снимка выбранной
  недели. При отсутствии данных по одной из схем показывается известная часть
  (`stockPartial=true`). Если неизвестны обе схемы, показывается `—`.
  Итог складывает доступный сток всех отобранных строк, включая размеры.
- Возвраты берутся из сохранённого `wb_customer_transit`. Отдельная задача
  `wb_ephemerides_stock_snapshot` по понедельникам в 00:05 МСК фиксирует их
  вместе с сохранёнными FBS/FBO и суммой ФФ в `ephemerides_stock_snapshots`.
  Она не зависит от успеха или включения загрузки возвратов; отсутствующие
  компоненты остаются неизвестными.
  Повторные и ручные загрузки не перезаписывают недельный снимок. До первого
  понедельничного снимка, для новых товаров и недель без снимка показывается `—`.
  Подпись ячейки показывает неделю и время фиксации. Это правило действует
  только в эфемеридах, обычные остатки продолжают обновляться.
  В старых снимках без поля `ff` «На ФФ» остаётся неизвестным. Колонки «На ФФ»
  и «Сток, доступный к продаже» поддерживают сортировку, фильтрацию, скрытие и
  CSV-экспорт. Итоги суммируют ФФ
  всех отобранных строк, включая размеры, независимо от пагинации; возвраты
  по-прежнему учитываются один раз на nmID внутри магазина.
- «В пути на склады FBO» (`inboundFbo`) показывает текущий сохранённый снимок
  поставок WB и количество, оставшееся к приёмке. Это отдельная колонка
  при любой выбранной неделе. Неподтверждённые количества отображаются прочерком.
- `—` означает отсутствие данных. Подтверждённый ноль показывается только при
  наличии исходной строки или доказательства успешной загрузки дня. Известные
  части неполного показателя суммируются. В основной таблице и её итогах
  сведения о качестве доступны в подсказках.
- WB отдаёт заказы и рекламу на nmID, а каталог может содержать размеры. Строки
  размеров показывают общие метрики артикула; итоги сегодняшнего оборота, заказов, рекламы и
  возвратов считают nmID один раз **внутри магазина**. Размерные планы/складские
  остатки и ТО по цели суммируются. При противоречивых общих значениях итог не выдумывается.

Чтение страниц/API не вызывает внешние API и ничего не записывает. История
комментариев загружается отдельно, без расчёта экономики.
Обе недели используют один набор исходных данных на запрос (`analyzer.Sources`):
каталог, настройки, цены, рейтинг, заказы, рекламу и снимки экономики. Исторический
план извлекается при том же чтении снимков, без третьего разбора `economics_daily`.
Большие JSON читаются серверным курсором по 128 строк, разбираются один раз,
после чего архивные поля отбрасываются из памяти. Версия формулы, исходные
значения и ручные поправки сохраняются; содержимое БД не меняется.

## Ручная недельная цель

«Новая цель, шт» расположена сразу после «Цели недели» в блоке выбранной
недели WB. Введите целое неотрицательное количество. Поле сохраняется после
паузы во вводе, при выходе из ячейки и перед сменой недели. Ноль сохраняется
как значение, пустое поле очищает цель. В итогах и CSV используется сохранённое
количество.

«Обновить цели» сохраняет незавершённый ввод и применяет сохранённые значения
«Новая цель» выбранной недели по доступным товарам всех магазинов независимо
от фильтров на экране. После применения показатели «Цель недели», ТО по цели
и сегмент «Ниже цели» используют новую цель. Применение пустого поля возвращает
цель из источника. Исходное значение 1С хранится в прежнем источнике.

Ключ записи — магазин, полный артикул с размером и понедельник выбранной недели.
Редактировать можно текущую и доступные завершённые недели.
`PUT /api/analytics/ephemerides/goals` принимает `store, article, week, quantity, version`.
Версия 0 создаёт запись. При конфликте сервер возвращает HTTP 409 и последнюю
сохранённую цель. Кнопка ячейки «Загрузить сохранённое» обновляет значение и версию.
`POST /api/analytics/ephemerides/goals/apply` принимает понедельник `week`,
атомарно применяет цели и возвращает число изменённых товаров.

## Комментарии

Ключ: `(store_slug, полный article, понедельник недели, kind)`. Виды:
`competitor` (конкуренты), `decision` (решения), `next` (на следующую неделю).
Разные виды не объединяются и не перезаписывают друг друга. На странице истории
вид выбирается переключателем; отображаются 12 недель, дата позволяет открыть
более ранний интервал. В карточке товара доступны все три вида.

Блок «Комментарии по неделям» в эфемеридах показывает `decision` за шесть недель —
те же записи, что и «История комментариев» при выборе «Решения». Они используют
один ключ и состояние, поэтому изменение текущего решения сразу отражается в блоке.
Недельная сводка решений и решения на странице истории (включая карточку) доступны
только для чтения: текст без поля ввода. Запись выполняется в «Решениях» текущей
недели на основной странице или в её карточке. Если решения за прошлую неделю
никогда не было, ячейка пустая, без заглушки и кнопки; история существовавшей, но
очищенной записи остаётся доступна. Виды `competitor` и `next` не переименовываются
и не переносятся, их прежние правила редактирования сохраняются.

Текст до 4000 символов. Автосохранение через 5 секунд после ввода, при выходе из
поля и перед переходом между страницами. Ввод во время запроса сохраняется
следующей версией, ответ старого запроса его не стирает. Ошибки оставляют черновик
в открытой странице; перед закрытием есть предупреждение. Черновики не пишутся
в общее хранилище браузера. Настройки вида таблицы сохраняются в localStorage. В настройках можно скрывать
как блоки, так и отдельные столбцы; основная карточка товара остаётся видимой.
Артикул копируется при наведении и нажатии, включая отдельный столбец артикула.

Создание требует `version=0`, изменение — полученный номер версии. Уникальный
ключ и compare-and-swap защищают от двух писателей, включая разные процессы.
Изменение и запись ревизии атомарны. Очистка текста создаёт новую ревизию.
HTTP 409 требует сравнения с сохранённой версией: кнопка `↶` открывает историю
и позволяет принять серверный текст или явно сохранить свой новой версией.

## Доступ и HTTP

Раздел использует существующий `SectionName.EPHEMERIDES`; по умолчанию наследует
доступ к экономике WB. Проверяются права раздела, площадка, магазин и менеджер
товара. Это действует также для сохранения и просмотра ревизий. READ запрещает
запись. При WRITE «Решения» (`decision`) можно создавать, изменять и очищать
только за текущую календарную неделю по Москве (понедельник–воскресенье), независимо
от выбранной недели. Решения прошлых недель и их ревизии доступны для просмотра
в основной таблице, карточке товара и истории; сервер отклоняет их сохранение с HTTP 403.
Для `competitor` и `next` сохраняется редактирование текущих и прошлых недель.
Правило повторно проверяется при сохранении, в том числе после смены недели в открытой вкладке.

| Метод и путь | Действие |
|---|---|
| GET `/api/analytics/ephemerides?week=YYYY-MM-DD` | Две недели и комментарии |
| GET `/api/analytics/ephemerides/comments?week=YYYY-MM-DD` | Каталог и комментарии за 12 недель |
| PUT `/api/analytics/ephemerides/comments` | JSON `store, article, week, kind, text, version` |
| GET `/api/analytics/ephemerides/comments/revisions` | Параметры `store, article, week, kind` |

В GET дата нормализуется к понедельнику, в ключе записи требуется сам понедельник.
Выбирать можно недели с 03.01.2000 по текущую. Сохранение возвращает автора, UTC
время и новую версию. Экспорт CSV выгружает отфильтрованные строки и видимые
колонки, экранирует формулы Excel в текстовых значениях.

## Схема и фоновая загрузка

`app/infrastructure/ephemerides_orm.py` регистрирует пять таблиц:
`ephemerides_comments`, `ephemerides_comment_revisions`, `wb_customer_transit`,
`ephemerides_stock_snapshots` (одна неизменяемая запись на магазин и понедельник)
и `ephemerides_weekly_goals` (введённое и применённое количество, версия по магазину,
артикулу и неделе).
Они регистрируются в обычном `init_db()` через `create_all`. Старые таблицы и
данные не преобразуются; комментарии анализатора остаются самостоятельными.

Задание `wb_customer_transit_sync` раз в 4 часа получает существующим WB-адаптером
полный отчёт остатков, затем атомарно заменяет отдельный снимок возвратов магазина.
При ошибке сохраняет предыдущий снимок и отмечает ошибку в журнале заданий.
Задание доступно в стандартной панели интеграций, поддерживает выбор магазинов
и ручной запуск. Автозапуск зависит от общей настройки фоновых загрузок.
До первой успешной загрузки возвраты показываются как неизвестные.

Недельный сток фиксирует отдельная задача из `app/jobs/wb_ephemerides.py` через
типизированный `EphemeridesStockSnapshot` и `app/infrastructure/ephemerides_stock_repository.py`.
Она только читает сохранённые источники и не изменяет основные остатки.
При первом запуске в понедельник после 00:05 снимок создаётся сразу; в другие
дни пропущенный понедельник не подменяется текущими данными. После ошибки
есть три повтора. Повторная фиксация защищена ключом магазина и недели в БД.

## Проверки

При ручной проверке сверяют
ранжирование всех трёх отчётов по сегодняшнему дню при выборе прошлой недели,
изоляцию магазинов, различие нуля и неизвестного значения, однократную загрузку
источников эфемерид и сохранность JSON снимков на отдельной копии БД.
В интерфейсе проверяют идентификаторы столбцов,
сортировку, полноту итогов и исключение повторов размеров в сегодняшнем ТО.

При выпуске 09.10.2026 значения текущего и исторического периодов всех трёх
отчётов дополнительно сравнивались на одном экспортированном снимке PostgreSQL
в транзакциях только для чтения: совпали все прежние поля, кроме намеренно
изменённого порядка строк. На 2296 товарах текущие эфемериды формировались
около 22 секунд вместо 60–68, анализатор — около 10 вместо 17–18 секунд.
Это время серверной сборки без сети и отрисовки, а не гарантия для любого периода.
