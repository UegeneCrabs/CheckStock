# Эфемериды WB

Раздел **Аналитика → Эфемериды**: `/analytics/ephemerides`. История комментариев:
`/analytics/ephemerides/comments`. Используется оформление анализатора и расположение
блоков из HTML-макета: сводка магазинов, реквизиты, остатки, контроль, предыдущая и
выбранная недели, недельные комментарии. Поставщик удалён, категория одна.
Заголовки, итоги и ячейки используют общую палитру анализатора: реквизиты — сиреневые,
остатки — голубые, контроль — жёлтый, предыдущая неделя — сине-фиолетовая,
выбранная — зелёная, комментарии — бежевые. При наведении цвет блока сохраняется.
После успешной загрузки основная страница не показывает информационную надпись
о дате сохранённых данных; сообщения загрузки и ошибок остаются в строке состояния.
Статус сохранения комментариев и кнопка повторного сохранения находятся рядом
с заголовком «Эфемериды WB». Пустая строка загрузки не занимает место.
Поиск и переключатели «Все товары», «Ниже цели», «ROI < 0» расположены слева
в одном ряду у нижнего края верхнего блока, ближе к основной таблице; если места
мало, переключатели переносятся под поиск.
Сводка магазинов прижата к правому краю. Переключатель находится в заголовке
столбца «Магазин»: в свёрнутом виде показывается одна строка «Все магазины»,
в развёрнутом — отдельная строка каждого магазина. Общий итог учитывает фильтры
основной таблицы, не дублирует показатели артикула по размерам, а процент отклонения
рассчитывает от общих сумм. Состояние хранится в настройках вида в localStorage.
При сворачивании освобождается место для основной таблицы. На узком экране сводка
переходит под них. «История комментариев» и «Экспорт» находятся в панели основной
таблицы рядом с выбором недели и колонок. Кнопка «Все поля» сразу возвращает
таблицу к самому левому краю. Остальные кнопки совмещают начало выбранного блока
с правой границей закреплённого столбца «Товар» по фактическому положению ячеек,
чтобы первые столбцы блока не скрывались при переходе.
Шапка таблицы компактная: группы — 24 px, названия столбцов — от 56 px, итоги — 24 px.
Она закрепляется при вертикальной прокрутке целиком, поэтому переносы названий
не приводят к наложению строк и визуальному сужению итогов.

## Периоды и источники

- Неделя ISO, понедельник–воскресенье; дата «сегодня» определяется по Москве. Текущая
  неделя считается по сегодня включительно, будущие дни не становятся нулями.
- По умолчанию товары ранжируются по **ТО за сегодня**, по убыванию, независимо
  от выбранной недели. Столбец «ТО сегодня, ₽» находится в реквизитах товара;
  неизвестный ТО идёт после известных значений, включая подтверждённый ноль.
  Ручная сортировка по другим столбцам доступна; сброс возвращает сегодняшний ТО.
- **ТО эфемериды** — сумма `wb_funnel_daily_orders.orders_amount` за дни выбранной
  недели. Это валовая сумма заказов без вычитания отмен и без умножения на выкуп.
  Факт недели в штуках — сумма сохранённых количеств заказов.
- Сводка магазинов наверху показывает сегодняшний оборот, как анализатор, отдельно
  от недельного ТО. Прогноз использует действующий коэффициент анализатора D=1.
  Сводка учитывает отбор товаров, отображается без подписи над таблицей и без
  внутренней прокрутки; все строки видны, текст переносится по ширине ячеек.
- ROI, ДРР, CTR и полнота источников используют правила `app/analytics/analyzer.py`.
  CTR считается отношением суммы кликов к сумме показов; ДРР — рекламных расходов
  к ожидаемой сумме выкупа за совпадающие дни. ROI — из дневных снимков экономики.
- Цены, СПП, кошелёк — последний сохранённый снимок **внутри соответствующей
  недели**, без подстановки сегодняшней цены за прошлую неделю.
- План текущей недели — текущий справочник 1С. План прошлой недели — последнее
  сохранённое `source.raw.reference.goal_week` внутри недели из `economics_daily`.
  Старые снимки без этого поля остаются без плана; история не восстанавливается
  сегодняшними данными. Планы показаны в штуках и доступны только для чтения.
- Менеджер, категория, проект, ABC-D — справочники/каталог БД; рейтинг и складские
  остатки — текущие сохранённые значения независимо от выбранной недели.
- Общий сток = FBS + FBO + в пути от клиента. ФФ сюда не входит. Возвраты берутся
  из `wb_customer_transit`; подпись ячейки показывает время снимка.
- `—` означает отсутствие данных. Подтверждённый ноль показывается только при
  наличии исходной строки или доказательства успешной загрузки дня. Известные
  части неполного показателя суммируются. Все ячейки, итоги и сводка магазинов
  отображаются без звёздочек.
- WB отдаёт заказы и рекламу на nmID, а каталог может содержать размеры. Строки
  размеров показывают общие метрики артикула; итоги оборота, заказов, рекламы и
  возвратов считают nmID один раз **внутри магазина**. Размерные планы/складские
  остатки суммируются. При противоречивых общих значениях итог не выдумывается.

Чтение страниц/API не вызывает внешние API и ничего не записывает. История
комментариев загружается отдельно, без расчёта экономики. Архив сырьевых событий
`economics_daily_events` для этих страниц не читается.
Обе недели используют один набор исходных данных на запрос (`analyzer.Sources`):
каталог, настройки, цены, рейтинг, заказы, рекламу и снимки экономики. Исторический
план извлекается при том же чтении снимков, без третьего разбора `economics_daily`.
Большие JSON читаются серверным курсором по 128 строк, разбираются один раз,
после чего архивные поля отбрасываются из памяти. Версия формулы, исходные
значения и ручные поправки сохраняются; содержимое БД не меняется.

## Комментарии

Ключ: `(store_slug, полный article, понедельник недели, kind)`. Виды:
`competitor` (конкуренты), `decision` (решения), `next` (на следующую неделю).
Разные виды не объединяются и не перезаписывают друг друга. На странице истории
вид выбирается переключателем; отображаются 12 недель, дата позволяет открыть
более ранний интервал. В карточке товара доступны все три вида.

Блок «Комментарии по неделям» в эфемеридах показывает `decision` за шесть недель —
те же записи, что и «История комментариев» при выборе «Решения». Они используют
один ключ и состояние, поэтому изменение текущего решения сразу отражается в блоке.
Недельная сводка решений и решения на странице истории (включая карточку) доступны
только для чтения: текст без поля ввода. Запись выполняется в «Решениях» текущей
недели на основной странице или в её карточке. Если решения за прошлую неделю
никогда не было, ячейка пустая, без заглушки и кнопки; история существовавшей, но
очищенной записи остаётся доступна. Виды `competitor` и `next` не переименовываются
и не переносятся, их прежние правила редактирования сохраняются.

Текст до 4000 символов. Автосохранение через 5 секунд после ввода, при выходе из
поля и перед переходом между страницами. Ввод во время запроса сохраняется
следующей версией, ответ старого запроса его не стирает. Ошибки оставляют черновик
в открытой странице; перед закрытием есть предупреждение. Черновики не пишутся
в общее хранилище браузера. Настройки вида таблицы сохраняются в localStorage.

Создание требует `version=0`, изменение — полученный номер версии. Уникальный
ключ и compare-and-swap защищают от двух писателей, включая разные процессы.
Изменение и запись ревизии атомарны. Очистка текста создаёт новую ревизию.
HTTP 409 требует сравнения с сохранённой версией: кнопка `↶` открывает историю
и позволяет принять серверный текст или явно сохранить свой новой версией.

## Доступ и HTTP

Раздел использует существующий `SectionName.EPHEMERIDES`; по умолчанию наследует
доступ к экономике WB. Проверяются права раздела, площадка, магазин и менеджер
товара. Это действует также для сохранения и просмотра ревизий. READ запрещает
запись. При WRITE «Решения» (`decision`) можно создавать, изменять и очищать
только за текущую календарную неделю по Москве (понедельник–воскресенье), независимо
от выбранной недели. Решения прошлых недель и их ревизии доступны для просмотра
в основной таблице, карточке товара и истории; сервер отклоняет их сохранение с HTTP 403.
Для `competitor` и `next` сохраняется редактирование текущих и прошлых недель.
Правило повторно проверяется при сохранении, в том числе после смены недели в открытой вкладке.

| Метод и путь | Действие |
|---|---|
| GET `/api/analytics/ephemerides?week=YYYY-MM-DD` | Две недели и комментарии |
| GET `/api/analytics/ephemerides/comments?week=YYYY-MM-DD` | Каталог и комментарии за 12 недель |
| PUT `/api/analytics/ephemerides/comments` | JSON `store, article, week, kind, text, version` |
| GET `/api/analytics/ephemerides/comments/revisions` | Параметры `store, article, week, kind` |

В GET дата нормализуется к понедельнику, в ключе записи требуется сам понедельник.
Выбирать можно недели с 03.01.2000 по текущую. Сохранение возвращает автора, UTC
время и новую версию. Экспорт CSV выгружает отфильтрованные строки и видимые
колонки, экранирует формулы Excel в текстовых значениях.

## Схема и фоновая загрузка

`app/infrastructure/ephemerides_orm.py` добавляет три таблицы:
`ephemerides_comments`, `ephemerides_comment_revisions`, `wb_customer_transit`.
Они регистрируются в обычном `init_db()` через `create_all`. Старые таблицы и
данные не преобразуются; комментарии анализатора остаются самостоятельными.

Задание `wb_customer_transit_sync` раз в 4 часа получает существующим WB-адаптером
полный отчёт остатков, затем атомарно заменяет отдельный снимок возвратов магазина.
При ошибке сохраняет предыдущий снимок и отмечает ошибку в журнале заданий.
Задание доступно в стандартной панели интеграций, поддерживает выбор магазинов
и ручной запуск. Автозапуск зависит от общей настройки фоновых загрузок.
До первой успешной загрузки возвраты показываются как неизвестные.

## Проверки

`python -m unittest tests.test_ephemerides tests.test_analyzer -v`
проверяет реальные чтения/записи во временной SQLite, сроки/полноту, оборот,
изоляцию магазинов и менеджеров, конфликты, ревизии и сохранность старого снимка
при ошибке загрузки. DDL дополнительно компилируется диалектом PostgreSQL.
`node --test tests/test_ephemerides.cjs tests/test_analyzer.cjs` проверяет суммы,
размерные дубли и асинхронное сохранение. PostgreSQL runtime и настоящий WB API
нужно проверять отдельно при подготовке выпуска.

`python -m tests.preview_ephemerides` поднимает UI на `127.0.0.1:8876`
с синтетическими товарами и отдельной временной БД. Изменения комментариев в
этом предпросмотре затрагивают только временную БД, удаляемую при завершении.
