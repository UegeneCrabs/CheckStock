# История СПП WB в API сотрудников

Два метода чтения используют прежний персональный Bearer-ключ и доступны через
общую OpenAPI-схему и MCP. Они не запускают сбор цен, закрытие дня или запись в БД.
Миграции не нужны.

| GET-метод | Назначение |
| --- | --- |
| `/api/agent/v1/spp-hourly` | Сохранённые почасовые наблюдения `wb_hourly_prices`. |
| `/api/agent/v1/spp-daily` | Сохранённые дневные средние `wb_daily_prices`. |

Параметры: `marketplace=WB`, `store`, обязательные `date_from` и `date_to`,
необязательный точный `article`. Обе даты включены, период 1–90 дней, без будущих дат.
Если магазин не указан, действует общий поиск магазина по точному артикулу.
Для исторического товара, которого уже нет в каталоге, указывайте магазин явно.
Ozon и Яндекс не поддерживаются. Пагинация: `limit` 1–100, `offset`, `next_offset`.
`sort_by` поддерживает поля строки; по умолчанию время/дата по убыванию, `order=asc`
включает хронологический порядок. При одинаковой дате/времени порядок артикулов стабилен.

Почасовая строка: `article`, `observed_at`, `customer_price_with_spp`,
`spp_percent`, `customer_price_with_wallet`.
Дневная строка: `article`, `day`, `observed_at`, `average_customer_price_with_spp`,
`average_spp_percent`, `average_customer_price_with_wallet`.
Магазин и площадка находятся в общем конверте ответа. Цены — рубли, СПП — проценты.

Даты отбора соответствуют Москве. `observed_at` сохраняет исходный timestamp UTC
со смещением; у дневной записи это время последнего наблюдения, а не закрытия дня.
Часы прошлых дней после закрытия удаляются: для истории используйте дневной метод.
До закрытия дня дневного результата может не быть. Пропуски не заполняются,
`null` не заменяется нулём; `context.coverage=unknown` не обещает полноту наблюдений.
`total_rows` — число найденных записей, а не число товаров или часов без пропусков.

Дневные средние читаются без пересчёта: при закрытии применяются веса по
положительному сохранённому накопленному обороту в момент наблюдения. При отсутствии
положительных весов используется арифметическое среднее известных значений.
Это не среднее по каждой отдельной продаже. Цены и проценты не суммируются (`totals={}`).

Пример: `/api/agent/v1/spp-daily?store=rimili&marketplace=WB&date_from=2026-10-01&date_to=2026-10-07&limit=100`.
После выкладки обновите схему действия GPT. MCP обнаруживает методы через общий
список инструментов. Каталог показывает названия, параметры и поля обоих методов.

Проверки: `python -m unittest discover -s tests -p test_agent_spp_history.py -v`.


## Слои реализации

HTTP остаётся в общем роутере агентов. `SppHistoryQuery` и строки результата
определены в `app/dto/spp_history.py`. `SppHistoryService` использует порт
`SppHistoryRepository` из `app/application/ports.py`. SQLAlchemy-репозиторий читает
только нужные столбцы существующих таблиц; контейнер приложения собирает зависимости.
Оба диалекта используют параметризованный SQL; миграций и записи при чтении нет.
