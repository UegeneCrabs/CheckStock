# Claude и ChatGPT → CheckStock

С 10 октября 2026 года роли и индивидуальные ограничения отключены: активные пользователи имеют одинаковый доступ. Проверки сессий и принадлежности API/OAuth-ключей сохраняются. Актуальный контракт — [учётные записи и миграция](authentication.md).

MCP-сервис встроен в FastAPI-приложение. Адрес коннектора: `https://<домен-сайта>/mcp`.
Пользователь общается в своём Claude, подключает коннектор и разрешает доступ под
своим аккаунтом CheckStock. Все инструменты только читают данные.

## Что реализовано

- Полная инструкция из `static/agents/agent-instructions-full.txt` передаётся
  в MCP initialize.instructions и через инструмент getAnalyticsInstructions.
  Полная версия содержит указания по OAuth; добавлены явные умолчания для топа по ТО
  по всем доступным WB и правило ROI за тот же исторический период.
  Существенные ограничения данных должны оставаться видимыми в ответе.
  Перенесены используемые инструкцией ProductAnalysis и ProfitSummary из локальной
  версии GPT. После обновления переподключите коннектор и начните новый чат,
  чтобы клиент заново получил правила и список инструментов.

- Stateless Streamable HTTP с JSON-ответами: initialize, ping, tools/list, tools/call.
  Версии протокола: 2025-03-26, 2025-06-18, 2025-11-25. SSE-подписки и старый
  транспорт HTTP+SSE не используются (GET возвращает 405 после авторизации).
- Каталог инструментов строится из текущей схемы `/api/agent/v1/openapi.json`.
  Поддерживаются только существующие GET-операции этого API, без произвольных URL.
- OAuth authorization code + обязательный PKCE S256, dynamic client registration,
  discovery, привязка resource к точному адресу `/mcp`.
- Доступ на один час; rotating refresh token выдаётся после согласия пользователя
  также при одном scope `analytics:read`. `offline_access` принимается для
  совместимости, но не является условием выдачи токена продления.
  Само разрешение действует 30 дней. Повторное использование refresh token
  отзывает всё подключение. Для каждого пользователя не более 20 подключений.
- Подтверждение доступа в браузере после входа на сайт; CSRF cookie, одноразовая
  форма, проверка Origin, точные разрешённые redirect URI.
- Проверка активности и текущих прав пользователя при каждом MCP-запросе.
  API-обработчики вызываются внутри процесса с отдельным контекстом пользователя.
  Проверки магазинов, площадок и разделов остаются в существующих обработчиках.
  OAuth bearer не передаётся дальше и не принимается обычным REST API.
- Просмотр и отзыв своих подключений в разделе «ИИ-агенты».
- В хранилище сохраняются только хеши токенов, кодов и CSRF cookie.
  Названия подключений, ID пользователей и OAuth metadata хранятся открыто.

## Развёртывание командой сервера

### Автоматическое продление MCP

При обмене authorization code сервер возвращает access token на срок до одного часа
и refresh token до окончания исходного разрешения на 30 дней. Scope остаётся
согласованным пользователем: сервер не добавляет `offline_access` или новые права.
Refresh token привязан к тому же пользователю, клиенту, ресурсу и разрешению.
Успешное продление заменяет refresh token, поэтому клиент обязан сохранять и
использовать последнюю версию. Срок разрешения не сдвигается при продлении;
в последние минуты срок access token ограничен оставшимся временем.

Это устраняет прежнее условие, из-за которого клиент с одним `analytics:read`
не получал refresh token и терял доступ через час. Сервер не может обновлять токен
вместо клиента: автоматический OAuth refresh выполняет ChatGPT/Claude с выданным
refresh token. Срок самого access token увеличивать до 30 дней не требуется.

У ранее созданного подключения без refresh token он не появится задним числом:
после выкладки нужно один раз повторить OAuth-авторизацию. Подключения, уже
получившие refresh token, продолжают использовать его без замены. Миграций БД
и изменения схемы OAuth-хранилища нет. Отзыв, блокировка пользователя и окончание
разрешения прекращают доступ; повторное использование заменённого токена отзывает
всё подключение.

Проверки в `tests/agents/test_mcp_store.py` и `tests/web/routers/test_agent_mcp.py`
используют временные OAuth-хранилища и моделируют истечение времени без ожидания
часа. Проверяются выдача при одном scope чтения, обновление после истечения access
token, сохранение привязок и предельного срока, перезапуск хранилища, чужой
клиент/ресурс, ротация, replay, отзыв и неактивный пользователь. Это проверка
сервера и HTTP-протокола, а не доказательство поведения конкретной версии клиента.

2 ноября 2026 года выполнена дополнительная проверка реального ChatGPT через
временный HTTPS-туннель к локальному Linux/PostgreSQL-стенду. Подключение запросило
только `analytics:read`. На время проверки access TTL процесса был уменьшен до
60 секунд: после подтверждённого истечения токена клиент самостоятельно выполнял
refresh. Обезличенный аудит показал ротацию при неизменных grant, scope и предельной
дате разрешения, без повторного входа. Затем стандартный часовой TTL был восстановлен,
приложение перезапущено; тот же клиент получил часовой access token и продолжил работу.

Проверены получение общей инструкции с четырьмя разделами, обнаружение 44 инструментов
и четыре бизнес-запроса: магазины трёх площадок; полная и неполная прибыль Ozon;
отсутствующие сохранённые данные WB/Яндекса; товары Ozon с остатком без заказов.
Повторно прошли 28 серверных и 21 клиентская проверка, Ruff. Одна ошибка потока
ChatGPT до обращения к MCP устранена повтором запроса. Это результат локального
тестирования с синтетическими данными, не проверка выкладки на рабочий сервер.

### Порядок развёртывания

1. Установить обновлённый `requirements.txt` (добавлен httpx).
2. Задать переменные:

   ```text
   CHECKSTOCK_AGENT_PUBLIC_URL=https://<домен-сайта>
   CHECKSTOCK_MCP_DB_PATH=/app/agent-credentials/mcp_oauth.sqlite3
   CHECKSTOCK_SESSION_COOKIE_SECURE=1
   ```

   `CHECKSTOCK_AGENT_PUBLIC_URL` — только HTTPS origin, без пути и завершающего `/`.
   Без корректного значения MCP закрыт (503), а страница ИИ-агентов показывает,
   что подключение ещё не настроено.

3. Смонтировать `/app/agent-credentials` как постоянный **локальный** записываемый
   volume с правами только для UID приложения и администратора. SQLite-файл
   создаётся автоматически и хранится отдельно от основной БД сайта; миграции
   основной БД не нужны. Все workers одного сервера используют один файл.
   Для нескольких серверов/реплик на разных хостах требуется перенос OAuthStore
   в общую транзакционную БД. Не размещать SQLite на NFS.
4. HTTPS-прокси должен пропускать `/mcp`, `/.well-known/oauth-protected-resource`,
   `/.well-known/oauth-protected-resource/mcp`, `/.well-known/oauth-authorization-server`,
   `/oauth/mcp/*`. Сохранять Authorization, Origin, Accept, MCP-Protocol-Version.
   Не кешировать ответы. Настроить доверенные proxy IP согласно `agent-api-deployment.md`.
5. Ограничить частоту `/oauth/mcp/register` и `/oauth/mcp/token` на reverse proxy
   (например, 10 запросов/минуту/IP с небольшим burst для регистрации и
   60/минуту/IP для token). Учитывать общие исходящие IP Anthropic.
   Встроенный предел — 10 000 DCR-клиентов на 90 дней; при достижении новые
   регистрации временно отклоняются. Бэкап OAuth SQLite делать штатным SQLite
   backup API, а не копированием файла во время записи.
6. Не включать access/refresh tokens, Cookie и тела OAuth-запросов в журналы.
   На `/oauth/mcp/authorize` желательно логировать путь без query string.

По умолчанию разрешены точные callback `https://claude.ai/api/mcp/auth_callback` и
`https://chatgpt.com/connector_platform_oauth_redirect`.
`CHECKSTOCK_MCP_REDIRECT_URIS` позволяет задать точные HTTPS URI через пробел.
Не использовать wildcard и не добавлять произвольные домены.

## Подключение пользователем

1. В CheckStock открыть «ИИ-агенты» → «Подключить к Claude» и скопировать адрес.
2. В Claude открыть настройки коннекторов и добавить пользовательский коннектор
   с этим адресом. OAuth client ID/secret оставляются пустыми: используется DCR.
3. Нажать подключение. Если сессии сайта нет, страница предложит войти в новой
   вкладке; после входа вернуться и нажать «Продолжить после входа».
   Для выдачи разрешения нужно право изменения раздела «ИИ-агенты», как и для
   создания обычного API-ключа. Чтение отчётов сохраняет обычные права пользователя.
4. Проверить аккаунт на странице разрешения и подтвердить доступ.
5. Спросить Claude: «Какие мои магазины доступны?» Затем проверить один отчёт
   по известному артикулу и периоду. Отсутствующие данные не считать нулями.
6. Для отключения отозвать подключение в CheckStock → «ИИ-агенты».

## Проверки перед запуском

На изолированном окружении проверяют OAuth, PKCE, CSRF, resource, replay, expiry,
отзыв, изоляцию пользователей и магазинные права, протокол и валидацию аргументов.

После развёртывания отдельно проверить реальное подключение из Claude,
сертификат HTTPS, настройки прокси, сохранение подключения после перезапуска,
вход двух пользователей с разными магазинами и отзыв доступа.

## Откат

Вернуть предыдущую версию приложения. OAuth-хранилище сохранить в закрытом
volume. Для принудительного отключения всех подключений остановить сервис и
переместить OAuth SQLite в закрытый архив; новый файл потребует повторного согласия.
Не удалять файл `chatgpt_tokens.json`: существующие GPT-ключи независимы от MCP.

## ChatGPT / MCP

Страница `/ai-agents/gpt-mcp` доступна в общих вкладках и верхнем меню.
Она использует общий компонент списка MCP-подключений с Claude, но списки разделены:
`?provider=chatgpt` и `?provider=claude`. При обмене кода провайдер определяется по точному hostname выбранного и проверенного redirect URI, затем сохраняется в grants.provider. Список больше не зависит от срока жизни регистрации клиента или других разрешённых callback этого клиента.

Миграция OAuth SQLite добавляет nullable provider под BEGIN IMMEDIATE и заполняет старые записи до очистки истёкших клиентов. Однозначный hostname старой регистрации сохраняется как claude/chatgpt; отсутствующие или смешанные metadata дают unknown. Заполненный provider не пересчитывается. Токены, сроки и принадлежность доступа не меняются; повторная авторизация из-за этой миграции не нужна.

В ответе с фильтром connections содержит выбранный сервис, other_connections — неизвестные подключения пользователя. Обе вкладки показывают их отдельным блоком «Другие подключения MCP» с отзывом. Без фильтра connections сохраняет полный список, other_connections пуст. При отсутствии публичного URL список и отзыв остаются доступны. Отзыв проверяет владельца и прекращает действие токенов.

Проверки миграции и сохранения токенов: tests/agents/test_mcp_store.py; фильтрации и отзыва через HTTP: tests/web/routers/test_agent_mcp.py; обеих вкладок и ошибок отзыва: tests/agent_mcp_connections.cjs. OAuth использует отдельный SQLite-файл независимо от основной СУБД сайта; схема PostgreSQL этим изменением не затрагивается.
Существующий `/ai-agents/gpt` с Actions и API-ключами сохранён.

В ChatGPT Plugins добавьте custom MCP server, укажите публичный HTTPS `/mcp`,
выберите OAuth DCR, войдите в CheckStock и подтвердите доступ. CIMD не реализован.
Наличие этой функции зависит от настроек аккаунта/рабочего пространства ChatGPT.
Инструменты и общая инструкция поступают с сервера; после изменений обновите подключение.

OAuth metadata объявляет RFC 9207; успешный ответ и отказ пользователя возвращают
`iss`, совпадающий с issuer и authorization_servers. Невалидные запросы возвращают
локальную HTTP-ошибку без перенаправления. Это позволяет использовать стабильный
callback ChatGPT. Если CHECKSTOCK_MCP_REDIRECT_URIS задан явно, он полностью заменяет
список по умолчанию: администратор должен включить оба нужных точных URI.
Для подключения с другим callback скопируйте точный URI из настроек ChatGPT;
не разрешайте wildcard. Подтверждение доступа принимает Origin только сайта,
регистрация/обмен токенов также допускают Origin ChatGPT и Claude.

Проверка `tests/web/routers/test_agent_mcp.py` проходит DCR, подтверждение/отказ,
PKCE-обмен для обоих callback, issuer и запрет посторонних redirect/Origin.
Она не заменяет проверку реального подключения ChatGPT после развёртывания.
Источник требований: https://developers.openai.com/plugins/build/auth
