# Рейтинг склейки WB в API сотрудников

Два метода чтения входят в существующий `/api/agent/v1`, общую схему GPT Actions и единое MCP-подключение. Bearer-ключи и OAuth продолжают действовать. Поддерживается только `marketplace=WB`; для Яндекса и Ozon каталог показывает отсутствие поддержки этих методов.

| GET-метод | Назначение |
| --- | --- |
| `/api/agent/v1/rating-comparison` | Последние сохранённые оценки двух соседних равных периодов, изменение, состояние и итоги по карточкам. |
| `/api/agent/v1/rating-history` | Каждый день выбранного периода: рейтинг склейки WB, число отзывов и фактическое время замера либо `null`. |

## Область показателя

Обязательная подпись в ответах ИИ — **«Рейтинг склейки WB»**, даже для запроса одного артикула. Индивидуальный рейтинг отдельного товара без склейки может отличаться; таких данных в БД нет. Артикул и `nm_id` идентифицируют карточку, а не доказывают наличие её индивидуального рейтинга. Отдельной подтверждённой идентичности склейки метод не возвращает. Число карточек нельзя выдавать за число уникальных склеек. Размеры одной карточки внутри магазина не дублируются.

В `context` находятся `rating_scope=wb_joined_products`, `rating_label`, `individual_rating_available=false`, `group_identity_available=false` и `count_basis=catalog_cards_not_distinct_joined_groups`. Названия, бренд, менеджер и категория относятся к каталогу, а не к историческому состоянию этих справочников.

## Даты и параметры

Обязательны `date_from` и `date_to`: включительно, 1–90 дней, без будущих дат. День определяется по Москве. Нужен `store` либо точный `article` с общим разрешением магазина; неоднозначный артикул требует выбора магазина. У истории `article` обязателен даже при указанном магазине. Допускается базовый артикул карточки WB либо точный артикул размера из каталога; несуществующая карточка истории даёт 404. Активная учётная запись и доступ к магазину WB проверяются перед чтением.

Предыдущий период вычисляется автоматически и непосредственно предшествует выбранному. Для 26 октября — 1 ноября 2026 года это 19–25 октября. Сравниваются последние сохранённые наблюдения внутри каждого периода, а не средние и не текущий кэш. Отсутствие одного периода даёт `change=null`, `status=no_data`. Наблюдение не переносится из более раннего периода. Фактические дни и время замеров возвращаются отдельно от границ периода.

Сравнение поддерживает `article`, `search` по артикулу/названию, `brand`, `manager`, `subject`, `status`, `rating_below`, `drop_at_least`, `tolerance`. Фильтры справочников не зависят от регистра. `rating_below` — строго ниже заданного рейтинга выбранного периода; `drop_at_least` — снижение не меньше заданного числа пунктов, включительно. Эти фильтры исключают неизвестные значения.

`tolerance` по умолчанию 0. Состояние `problem` означает `change < -tolerance`; равенство границе допустимо. `healthy` означает только отсутствие падения больше допуска, а не высокий абсолютный рейтинг. `no_data` означает недостаточность исторических значений. Пороговые параметры конечные, от 0 до 5. Изменение выражается в пунктах рейтинга: 4,8 → 4,5 даёт −0,3 пункта, не −0,3%.

Общая пагинация: `limit` 1–100, `offset`, `next_offset`. По умолчанию сравнение сортируется по `change` по возрастанию, история — по `day` по возрастанию; `order=desc` меняет направление. Неизвестные значения идут последними. Итоги вычисляются до пагинации по всей отфильтрованной выборке и повторяются на страницах; суммировать их повторно нельзя.

## Поля сравнения

- Идентификация: `store_slug`, `nm_id`, `article`, `name`, `brand`, `manager`, `subject`.
- Выбранный период: `current_rating`, `current_observed_day`, `current_observed_at`.
- Предыдущий период: `previous_rating`, `previous_observed_day`, `previous_observed_at`.
- Результат: `change`, `status`.
- Отдельный свежий кэш: `latest_rating`, `reviews_count`, `latest_observed_at`; его дата может находиться за пределами выбранного периода.
- `context.previous_from/previous_to` — границы сравнения; `totals.checked/problem/healthy/no_data` — карточки всей отфильтрованной выборки, а не только страницы.

## Поля истории

Идентификация карточки и `day`, `rating`, `reviews_count`, `observed_at`. На каждый день есть строка; без сохранённого наблюдения три последних значения равны `null`. Ноль отзывов остаётся известным нулём. `totals.expected_days/observed_days/missing_days` относятся ко всему интервалу; `context.coverage_complete` подтверждает наличие замеров каждого дня, а не завершённость сегодняшнего дня.

## Источники и границы

Используются существующие `stock_items`, категории, справочник менеджеров, `wb_product_rating_daily` и текущий кэш `unit_economics_1c_product_reputation`. Прикладной сервис принимает именованные DTO, инфраструктура читает БД асинхронно. Методы не меняют данные, не запускают сбор WB, не создают таблицы, не интерполируют и не заполняют прошлое текущим рейтингом. Оценки 0/неизвестные не считаются достоверным рейтингом. Тексты отзывов, распределение звёзд, история состава склейки и доказанная причина падения в эти методы не входят.

При запросе конкретного артикула чтение дневных снимков и текущего кэша ограничивается его `nm_id`; поиск карточки и фильтры по-прежнему проверяют каталог магазина. Запрос без артикула охватывает карточки магазина целиком.

Полные MCP-правила и компактные правила GPT Actions дополнены методами, их единицами, пропусками и ограничением склейки. Запрос «последние 7 дней» означает семь полных дней без сегодняшнего. Для всех магазинов ИИ обходит доступные WB-магазины через прежнее единое подключение.

## Проверка

Проверки включены в существующий `tests/web/routers/test_agent_full.py`: сравнение равных периодов и фактических дат, отдельный кэш, размеры карточки, изоляция магазинов, пороги, фильтры, итоги до пагинации, пропуски, ноль отзывов, 401/403/404/422, схема и каталог. Синтетические данные для внешней проверки создаются только в существующих таблицах изолированного локального PostgreSQL с названиями `[ТЕСТ API]`.
