# Юнит-экономика Яндекс Маркета

Страница `/sales/unit-economics-1c/yandex-market` читает данные из БД. В HTTP-запросе страницы обращения к API нет.

| Показатель | Источник и расчёт |
| --- | --- |
| FBS, FBO, ФФ | `mp_stock` и сумма `ff_stock` по кабинету, артикулу и `YANDEX MARKET`. FBY хранится как `fbo`. |
| Всего | FBS + FBO + ФФ, как у WB. |
| Хватит, дней | Всего × 21 / количество заказанных единиц за 21 день, включая сегодня. Общая функция WB; при известном нулевом спросе результат 0. |
| ТО | Сумма заказов минус сумма отмен за 7 завершённых дней по дате заказа, МСК. |
| Рейтинг, отзывы | `rating`, `currentOpinionCount` из отчёта `goods-feedback`, сопоставление по артикулу или `mp_sku`. Повторы SKU по кампаниям не суммируются. |
| Затраты | `billedAmount` из буста продаж + `cost` из товарного листа буста показов за тот же период. Для буста показов API даёт расчётные расходы по товарам. |
| CTR | Сумма рекламных кликов / сумма рекламных показов × 100. Органические показы и клики исключены. |
| CPC | Общие затраты / рекламные клики. При нулевом знаменателе CTR/CPC равны 0, как у WB. |
| ДРР с выкупом | Общая функция WB: затраты / сумма заказов до отмен / доля выкупа × 100. Доля выкупа ЯМ — доставленные / (доставленные + отменённые) единицы из заказов периода. При нулевой доле применяется существующее правило WB — 100%; при нулевом ТО результат 100% с затратами, иначе 0%. |

Маржа, ROI, цены и редактирование калькулятора ЯМ пока остаются неподключёнными.

## Обновление

Новая фоновая загрузка `yandex_unit_economics_sync` работает раз в час, если фоновые загрузки включены. Она учитывает включённые кабинеты ЯМ в настройках загрузок. Для ручного запуска:

```powershell
.venv/Scripts/python.exe scripts/sync_unit_economics_yandex.py --store rimili
```

Ключи берутся из существующих настроек ЯМ. При неоднозначном кабинете требуется настроенный `business_id` либо однозначный набор `campaigns`.

Заказы нормализуются существующей функцией ЯМ, но сохраняются отдельно: загрузка не меняет `sales_order_lines`, RNP и таблицы WB. До первой успешной загрузки используются уже имеющиеся заказы ЯМ из БД. Результаты API хранятся в новой таблице `unit_economics_yandex_snapshots`, которую создаёт обычный `db.init_db()`.

Каждый источник сохраняется после полного успешного чтения. Ошибка одного источника не мешает другим и не стирает последние данные. Сводная реклама публикуется только после получения обоих отчётов; отчёт за другой период не выдаётся за текущие семь дней. Отсутствующие данные показываются прочерками, успешный пустой рекламный отчёт — нулями. Ошибки доступны в статусах загрузок и в `error` снимка.

## Контракты API

- [Заказы](https://yandex.ru/dev/market/partner-api/doc/ru/reference/orders/getBusinessOrders): диапазон начала включительный, конца исключительный; пагинация.
- [Отзывы](https://yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateGoodsFeedbackReport): лист `paid_opinion_models`.
- [Буст продаж](https://yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateBoostConsolidatedReport): лист `business_boost_consolidated`, рекламные поля `showsWithFee`, `clicksVendorWithFee`.
- [Буст показов](https://yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateShowsBoostReport): только лист `business_shows_boost_consolidated_offers`; итог кампаний повторно не складывается с товарами.

Ключ API не передаётся при скачивании отчётов по подписанным ссылкам.
