# Юнит-экономика Яндекс Маркета

Страница `/sales/unit-economics-1c/yandex-market` читает данные из БД. В HTTP-запросе страницы обращения к API нет.

## Актуальный ассортимент

С 17.09.2026 фиксированный список артикулов не ограничивает юнитку. Показываются
неархивные товары с ненулевым ТО за выбранный период либо положительным остатком
FBS, FBO, ФФ или подтверждённым количеством в пути. Карточки и история из БД не удаляются.
Архив загружается при синхронизации каталога через `offer-mappings` с `archived=true`
и хранится отдельным снимком `archive`; при ошибке остаётся предыдущий снимок.

В колонке «В пути на склады FBO» используются сохранённые API-поставки: учитываются
утверждённые заявки (`ACCEPTED_BY_WAREHOUSE_SYSTEM`) и отправленные поставки;
черновики, отменённые и завершённые исключаются. Из приёмки вычитаются уже принятые
единицы. Если по части поставок количество неизвестно, известная часть остаётся
видимой со знаком `≥` и жёлтой подсветкой; отсутствие принятых количеств в API не
подменяется нулём. Полностью неизвестные или устаревшие количества показаны прочерком.
Это правило утверждённых заявок включено только для юнитки ЯМ; общая выгрузка стока
сохраняет прежний состав поставок и требует полного количества.
В доступный остаток и его запас в днях поставки ещё не включаются.

Итоги в шапке учитывают все строки после фильтрации, независимо от пагинации.
Проценты пересчитываются из сумм числителя и знаменателя; неполные итоги подсвечены.
ДРР считается за пересечение загруженных дней рекламы и заказов, с перечислением
дат в подсказке. Расходы на рекламу отдельно суммируются за все доступные дни.

Произвольный период передаётся в API и сохраняется в URL. Устаревший ответ запроса
не может заменить более новый выбранный период. Пока открыт калькулятор ЯМ или
редактируется поле страницы, автоматическое обновление таблицы отложено.

| Показатель | Источник и расчёт |
| --- | --- |
| FBS, FBO, ФФ | `mp_stock` и сумма `ff_stock` по кабинету, артикулу и `YANDEX MARKET`. FBY хранится как `fbo`. |
| Всего | FBS + FBO + ФФ, как у WB. |
| Хватит, дней | Всего × 21 / количество заказанных единиц за 21 день, включая сегодня. Общая функция WB; при известном нулевом спросе результат 0. |
| ТО | Сумма заказов минус сумма отмен за выбранный период завершённых дней по дате заказа, МСК. По умолчанию 7 дней; доступны 14, 30 и произвольный период до 366 дней. |
| Рейтинг, отзывы | `rating`, `currentOpinionCount` из отчёта `goods-feedback`, сопоставление по артикулу или `mp_sku`. Повторы SKU по кампаниям не суммируются. |
| Затраты | `billedAmount` из буста продаж + `cost` из товарного листа буста показов за тот же период. Для буста показов API даёт расчётные расходы по товарам. |
| CTR | Сумма рекламных кликов / сумма рекламных показов × 100. Органические показы и клики исключены. |
| CPC | Общие затраты / рекламные клики. При нулевом знаменателе CTR/CPC равны 0, как у WB. |
| ДРР с выкупом | Общая функция WB: затраты / сумма заказов до отмен / доля выкупа × 100. Процент выкупа берётся из отдельной загрузки; при отсутствующем или нулевом значении используется процент по умолчанию из настроек ЯМ. Если он тоже не задан, функция ДРР применяет 100%; при нулевой сумме заказов результат 100% с затратами, иначе 0%. |

Цена продавца и цена покупателя без Пэй загружаются в БД отдельным
[сборщиком витрины](yandex-storefront-prices.md) и отображаются в калькуляторе.
Текущие маржа на штуку и ROI используют дневные показатели. Исторические итоги —
сохранённые дневные расчёты; пропуски показаны в подсказках жёлтых ячеек.

ЯМ может вернуть `clicks: null` в рекламном отчёте для товара без кликов.
Такое значение учитывается как 0 кликов; расходы и показы товара сохраняются.
Отсутствующая колонка кликов, некорректные числа и отсутствующие расходы или
показы по-прежнему считаются ошибкой загрузки всего рекламного снимка.

## Обновление

### Новизна товара

Статус хранится отдельно в `unit_economics_yandex_product_statuses` по паре
«магазин + артикул»: `new` — «Новинка», `old` — «Обычный».
Он не связан с `is_legacy` (видимостью ассортимента).

Для текущей даты D по МСК проверяется неделя **D−28 … D−22 включительно**.
Например, 31 августа проверяются 3–9 августа. Если хотя бы в один день есть
хотя бы один заказ, статус становится `old` навсегда. Учитываются заказы,
включая впоследствии отменённые; тестовые заказы исключает загрузчик API.
`order_date` хранит найденную дату заказа в этой неделе, а не дату первой
продажи за всё время. Поле «дней в продаже» по этой проверке не вычисляется.

Если заказов нет, сохраняется `new`; такие товары проверяются ежедневно.
Используется отдельная задача `yandex_product_novelty_sync` — раз в сутки,
первый запуск через 180 секунд после старта. Проверяются товары выбранного
ассортимента; уже обычные товары и проверенные сегодня новинки пропускаются.
Если в магазине больше нечего проверять, API не вызывается. При добавлении
нового товара он попадёт в следующий запуск.

Проверка читает всю неделю через API заказов, не расширяя текущую загрузку
последних 7 дней и не изменяя снимки экономики, рекламы или остатков.
Ошибка API, в том числе на следующей странице заказов, сохраняет прежние
статусы. До первой успешной проверки в колонке стоит «— / Не проверен».
После проверки отображаются «Новинка» или «Обычный»; фильтр «Новинки» включён.

Ручной запуск: `.venv/Scripts/python.exe scripts/sync/sync_unit_economics_yandex.py --store rimili --source novelty`.

### Метрики

Данные 1С для ЯМ загружаются из единственного листа `YM` общей Google-таблицы
`1q0WL6OB3Edh2O1ogqx7CK3MAij3O6xjD6gE0i3q3qEY`. Строка определяется парой
`Магазин` + `ARTICLE`. Алиасы: ХочуШар → RIMILI, BTH → TRUSTHOME,
Гоголь → GOGOL; регистр и окружающие пробелы не влияют на сопоставление.

Текущие значения сохраняются отдельно в `unit_economics_yandex_source_values`:
закупка, фулфилмент, процент маркетинговых затрат, менеджер (необязательная
колонка), исходный тег и его части, внешний артикул и его части, лист, строка
и время обновления. Как у WB, процент сохраняется для каждого товара;
самое частое значение также записывается в настройки магазина с
`marketplace='YANDEX MARKET'`. Значения WB не изменяются импортом ЯМ.

Сохраняются все корректные строки листа, включая товары без загруженной
карточки. Это не расширяет ассортимент юнит-экономики. При загрузке карточки
данные подхватываются по магазину и артикулу. В таблице отображаются цели,
статус остатков и ABC/факт/план; в карточке — закупка и фулфилмент.
Расчёты маржи, ROI и остальные показатели эта загрузка не меняет.

Общая задача `unit_economics_1c_source_sync` («Данные 1С») обновляет WB и ЯМ
ежедневно в час, заданный для WB (по умолчанию 02:00 МСК). Та же функция
вызывается существующей кнопкой «Выгрузить себес» в настройках кабинетов.
Оба источника обрабатываются независимо: ошибка одного не мешает загрузить
другой, а результат кнопки и журнал сообщают об ошибке и успешной части.
Отсутствующий лист/заголовок, неизвестный магазин, конфликтующие дубликаты
и ошибка API сохраняют предыдущий снимок ЯМ. Успешный импорт атомарно заменяет
его целиком без истории, как загрузка WB.

Заказы, выкуп, отзывы и реклама обновляются независимыми фоновыми задачами.
У каждой свои переключатели магазинов, история запусков и ошибки в разделе интеграций.

| Загрузка | Интервал | Первый запуск после старта приложения |
| --- | --- | --- |
| `yandex_orders_sync` — Заказы Яндекс Маркета | 15 минут от начала запуска, как воронка WB | Через 5 секунд |
| `yandex_orders_previous_day_close_00_msk` — Закрытие заказов | Ежедневно 00:00 МСК | Ближайшие 00:00 МСК |
| `yandex_buyout_sync` — Процент выкупа | 4 часа от начала запуска, как WB | Сразу |
| `yandex_reputation_sync` — Отзывы и рейтинг | 24 часа от начала запуска | Через 120 секунд |
| `yandex_advertising_sync` — Реклама | 15 минут после завершения загрузки, как реклама WB | Через `wb_advertising_sync_startup_delay_seconds` (по умолчанию 10 секунд) |

Заказы обновляются за сегодня и 6 предыдущих дней по МСК. В полночь отдельно
перечитывается вчерашний день. Дневные строки сохраняются в
`unit_economics_yandex_daily_metrics` с ключом «магазин + источник + день + артикул».
Перезаписывается только успешно полученное окно, более старые дни не удаляются.
`unit_economics_yandex_loaded_days` отмечает полностью полученные дни, в том числе
дни без заказов/рекламы. Это позволяет отличать нулевые значения от отсутствия данных.

При инициализации БД существующие снимки заказов переносятся в дневную историю.
Миграция повторяемая: новые значения и уже загруженные пустые дни не перезаписываются.
Старый 21-дневный снимок остаётся только для совместимости, он не ограничивает
накопление дневной истории. Для дней, ещё не загруженных новым способом,
используются сохранённые заказы `sales_order_lines` и прежний снимок.

Реклама запрашивается отдельно за каждый день: оба товарных отчёта возвращают
итоги за весь переданный диапазон без разбивки по датам. Проверяется окно D−7 … D.
Сначала обновляется сегодня (кэш 15 минут), затем вчера (кэш 1 час), остальные
завершённые дни — не чаще раза в сутки. Отсутствующие дни загружаются независимо
от кэша, включая пустые дни с нулевой рекламой. Уже загруженная неделя не
перегенерируется каждые 15 минут; поздние начисления обновляются по указанному сроку.
Каждый день сохраняется
атомарно после получения обоих отчётов. Ошибка следующего дня не стирает уже
сохранённые дни. Старый недельный снимок может использоваться до заполнения дневной
истории только при точном совпадении запрошенного периода; по дням он не распределяется.

Генерация отчётов одного businessId последовательная. Для рекламного типа отчёта
соблюдается пауза 120 секунд после завершения предыдущего с запасом 5 секунд;
для аналитики продаж и отзывов — 600 + 5 секунд. Срок следующего запроса
сохраняется в `yandex_report_limits` до отправки запроса и уточняется после завершения.
Он переживает `uvicorn --reload`; блокировка кабинета общая для процессов одной БД.
При HTTP 420/429 дополнительно учитываются `X-RateLimit-Resource-Until` и `Retry-After`,
максимум три попытки. При повторном 420/429 ожидание увеличивается: 125, затем 250 секунд для рекламы
(или дольше, если это указано в заголовках ответа). После последней неудачной попытки
сохраняется срок ожидания для следующего запуска. Сетевые ошибки и HTTP 5xx при
генерации также повторяются через общий ограничитель, без коротких повторов внутри
API-клиента: даже при тайм-ауте Яндекс мог уже принять запрос и потратить квоту.
Квота стороннего приложения учитывается по ответу Маркета,
а не через локальную блокировку. На время ожидания квоты
блокировка кабинета освобождается, поэтому другие типы отчётов могут загружаться.
Ошибки доступа не
повторяются с такой задержкой. Магазины с разными businessId обрабатываются параллельно. Поэтому полный
обход рекламы занимает несколько минут, а фактическое расстояние между началами
рекламных циклов равно времени загрузки плюс 15 минут. Чтение страницы не вызывает API.

Отдельный выкуп использует `shows-sales` с группировкой `OFFERS`:
- числитель — `orderItemsDeliveredFromOrderedCount`;
- знаменатель — числитель + `orderItemsCanceledByCreatedAtCount` + `orderItemsReturnedByCreatedAtCount`;
- процент — числитель / знаменатель × 100, либо 0 при пустом знаменателе.

Все три показателя относятся к заказам, созданным в выбранном периоде.
Показатели по дате события не смешиваются с ними. Доставленные включают последующие
возвраты; возвраты учитываются в знаменателе вместе с отменами, как в определении
выкупа воронки WB. Явный `null` счётчика означает 0, отсутствие колонки — ошибку.

Период выкупа по умолчанию 14 завершённых дней, в настройках кабинетов ЯМ можно
выбрать 1–29 дней и процент по умолчанию. Настройки хранятся в
`unit_economics_1c_cabinet_settings` с `marketplace='YANDEX MARKET'`; параметры WB
и остальные параметры кабинета не изменяются. Новый период применяется при следующей
загрузке; старый отчёт другой длины не используется. Ручной запуск выкупа доступен
в строке «Процент выкупа Яндекс Маркета» раздела интеграций.
Сам выкуп, как у WB, хранится последним снимком с фактическим диапазоном и временем.

ТО и реклама суммируются по выбранному периоду из БД. При неполной истории ТО,
расходы, CTR и CPC показывают доступные данные с информацией о покрытии.
ДРР рассчитывается только при полном покрытии заказов и рекламы за одинаковый диапазон.
«Хватит, дней» всегда использует 21 день, включая сегодня, независимо от выбора
периода экономики; при неполной истории спроса показывается прочерк.
Прошлые даты не заполняются вымышленными нулями: годовой диапазон использует только
фактически накопленную историю. Автоматической выгрузки года назад нет, как у WB.

При ошибке API предыдущие успешные данные сохраняются. Текущие снимки источников
и их ошибки хранятся в `unit_economics_yandex_snapshots`. Загрузка не меняет
`sales_order_lines` и таблицы WB. Существующие переключатели общей старой
задачи переносятся на независимые задачи; новые выкуп и закрытие дня наследуют
настройки заказов один раз, без изменения уже настроенных переключателей.

Ручной запуск отдельного источника:

```powershell
.venv/Scripts/python.exe scripts/sync/sync_unit_economics_yandex.py --store rimili --source orders
.venv/Scripts/python.exe scripts/sync/sync_unit_economics_yandex.py --store rimili --source reputation
.venv/Scripts/python.exe scripts/sync/sync_unit_economics_yandex.py --store rimili --source advertising
.venv/Scripts/python.exe scripts/sync/sync_unit_economics_yandex.py --store rimili --source buyout
```

Ключи берутся из существующих настроек ЯМ. При неоднозначном кабинете нужен
настроенный `business_id` либо однозначный набор `campaigns`. Расписание работает
при запущенном приложении, включённых загрузках и выбранных кабинетах с API-ключами.
Маржа, ROI, логика новинок, импорт 1С и существующая выгрузка цен не меняются.

## Контракты API

Текущий источник — список отдельных заказов `/v1/businesses/{businessId}/orders`: позиции, суммы и статусы. [«Аналитика продаж»](https://yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateShowsSalesReport) — отдельный сводный отчёт с показами, кликами, корзинами, конверсиями и продажами; по назначению он ближе к воронке WB. ТО и история заказов остаются на API заказов. Для отдельного процента выкупа используется «Аналитика продаж»: только показатели заказов, созданных за выбранный период.

- [Заказы](https://yandex.ru/dev/market/partner-api/doc/ru/reference/orders/getBusinessOrders): диапазон начала включительный, конца исключительный; пагинация.
- [Отзывы](https://yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateGoodsFeedbackReport): лист `paid_opinion_models`.
- [Буст продаж](https://yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateBoostConsolidatedReport): лист `business_boost_consolidated`, рекламные поля `showsWithFee`, `clicksVendorWithFee`.
- [Буст показов](https://yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateShowsBoostReport): только лист `business_shows_boost_consolidated_offers`; итог кампаний повторно не складывается с товарами.

Ключ API не передаётся при скачивании отчётов по подписанным ссылкам.
