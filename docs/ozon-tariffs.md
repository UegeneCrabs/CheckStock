# Категории и тарифы комиссии Ozon FBO

Калькулятор использует официальный справочник Ozon, действующий с 7 октября
2026 года, проверенный 19 октября 2026 года. Это стандартные максимальные
ставки FBO без региональных коэффициентов, скидок и индивидуальных условий.
FBO ПВЗ, Fresh, FBS, realFBS и специальные программы не подменяют обычный FBO.

Источник: [Вознаграждение Ozon за продажу товаров](https://seller-edu.ozon.ru/libra/commissions-tariffs/commissions-tariffs-ozon/komissii-tovary-uslugi),
раздел «Таблица категорий с 7 октября 2026 г.» и
[официальный XLSX](https://cdn.ozone.ru/s3/ozon-disk-api/Seller-edu/files/commissions-tariffs/commissions/Tablica_kategoriy_dlya_rascheta_voznagrazhdeniya_07102026_1791447755.xlsx).
Лист `Прайс РФ (БЗ)`, A3:F9310: основная категория, категория, тип товара,
три ставки FBO. Сохранено 9308 строк; названия типов могут повторяться между
категориями. Идентификатор тарифа — SHA-256 нормализованной тройки названий,
не ID категории Seller API. Для каждой строки сохранён номер строки Excel.

## Поведение калькулятора

- Категория показана только в подробном расчёте, после ДРР за заказы и перед
  комиссией Ozon. Выбор использует общий с Яндекс Маркетом компонент:
  текущий тип и кнопка «Изменить», поиск по названиям и пути, переход по
  разделам и навигация с клавиатуры. Разделы строятся из справочника тарифов:
  основная категория → категория → тип товара. Выбрать можно только тип;
  одинаковые названия в разных разделах остаются отдельными вариантами.
  Постоянные пояснения, ссылка на тарифы и отдельная кнопка их применения
  под категорией убраны. Полный путь выбранной категории доступен при наведении.
  Переключение режима сохраняет категорию и рассчитанную комиссию.
- При открытии включён автоматический расчёт комиссии по цене с учётом акции.
  Для положительной цены до 100 ₽ включительно стандартная ставка — 17%,
  свыше 100 до 300 ₽ включительно — 23%. Правило действует автоматически
  в обоих режимах калькулятора.
- Текущие `description_category_id` и `type_id` читаются через
  `/v3/product/info/list`; названия — через `/v1/description-category/tree`.
  Дерево кешируется в памяти веб-процесса на час отдельно для Client-Id,
  конкурентные запросы используют один загрузчик. Карточка читается заново
  при открытии/сбросе. Ошибка не блокирует ручной выбор тарифа.
- Если название типа однозначно соответствует строке справочника, поле
  заполняется автоматически, а тариф передаётся как `product_tariff_id`.
  Сервер использует ставки этой строки для недорогих товаров, включая исключения.
  В текущем снимке 8707 строк имеют ставки 17%/23%, 601 строка — другие ставки.
  При нескольких совпадениях тариф не угадывается. Пока категория неизвестна
  или не сопоставлена, используются стандартные 17%/23%; индивидуальные
  исключения без сопоставления определить нельзя.
- Выбор полного варианта из списка, включая повторный выбор текущего типа,
  включает тариф FBO.
  После пересчёта связанных цен сервер выбирает ставку по `seller_price`
  (цена продавца с его акциями, до СПП и Кошелька): `<=100`, `>100 и <=300`,
  `>300`. Значение 100,01 относится ко второму диапазону.
- При изменении любой связанной цены сервер сначала восстанавливает цепочку цен,
  затем выбирает комиссию по получившейся `seller_price`, округлённой до копеек.
  Изменение процентов СПП/Кошелька тоже запускает этот расчёт, но сами проценты
  меняют только нижние цены цепочки и не уменьшают базу комиссии.
- Обычная ставка хранится отдельно в `regular_commission_percent`. При исходной
  цене выше 300 ₽ она берётся из комиссии товара; при исходной низкой/неизвестной
  цене — из `fbo_over_300` сопоставленной категории. При явном выборе категории
  используется её обычная ставка. Возврат цены выше 300 ₽ восстанавливает эту
  ставку, а не последнюю специальную. Если обычная ставка неизвестна и категория
  не сопоставлена, результат выше 300 ₽ остаётся неизвестным.
- При неизвестной цене автоматическая комиссия и её сумма неизвестны.
  Пустое значение остаётся `null`; некорректное число отклоняется. Цена 0
  не получает специальную ставку: используется обычная ставка, если она известна,
  и сумма получается 0. Комиссия в рублях округляется до копеек.
- Ручная правка процента/суммы включает `commission_mode=manual` и сохраняется
  до следующего изменения цены/скидки либо выбора категории. Следующая правка
  цены/скидки возвращает `automatic`; обычная ставка при ручном вводе не заменяется.
  Повторный выбор типа, включая тот же самый, включает справочник снова. Поиск и переходы по разделам
  сохраняют действующую комиссию до выбора типа. Закрытие поиска без выбора
  не меняет расчёт. Ошибку загрузки справочника можно повторить в самом поле.
- Сброс, закрытие и смена товара удаляют сценарий. Новое открытие/сброс заново
  берёт исходные цены, комиссию товара и категорию, применяя автоматическое правило.
  Все сценарии локальные: категория карточки Ozon, БД, дневные снимки
  комиссии и история маржи не изменяются.

Пример: 140729397, тип API 94637 «Смеситель», категория 17028737
«Сантехника». Строка 7143 справочника: 17%, 23%, 51%.
Для 300 ₽ сумма комиссии 69 ₽, для 300,01 ₽ — 153,01 ₽.

## HTTP и модули

Все маршруты требуют активного пользователя и включённой экономики Ozon.

- `GET /api/unit-economics-1c/ozon/tariffs`: `OzonTariffCatalog`, метаданные
  версии/источника/контрольной суммы, строки со ставками и названиями.
- `GET /api/unit-economics-1c/ozon/category?store=...&article=...`:
  `OzonCategorySelection`, проверка доступности кабинета, 403 для чужого или
  неизвестного кабинета, 502 `ozon_category_unavailable` при ошибке источника.
- `POST /api/unit-economics-1c/ozon/prices/calculate`: добавлено необязательное
  `tariff_id` для явного выбора категории и `product_tariff_id` для автоматически
  сопоставленной категории товара. Неизвестный ID и будущая редакция дают 422.
  Без ID действует стандартное правило недорогих товаров. Ответ
  `OzonPriceCalculation` дополнен `regular_commission_percent` и
  `commission_mode=automatic|manual`; их нужно возвращать в `values` следующего
  запроса. Старые поля и независимый расчёт `/commission/calculate` сохраняются.
  При `initialize=true` обычная ставка определяется по исходным значениям до
  применения `edits`; специальная ставка низкой исходной цены не становится
  обычной ставкой для высоких цен.

Сервис: `app/application/ozon_tariffs.py`, сборка: `app/container.py`,
DTO: `app/dto/ozon_tariffs.py`, API: `app/ozon/async_categories.py`,
нормализация: `app/ozon/tariff_normalizer.py`, справочник:
`app/infrastructure/ozon_tariff_catalog.py` и
`app/ozon/data/commission-tariffs.json`, UI:
`static/economics/ozon/categories.js` вместе с `prices.js`. Общий выбор:
`static/economics/shared/categories.js`, `categories.css` и
`templates/economics/shared/client/categories.html`. Он сохраняет классы
и атрибуты исходного компонента ЯМ; `static/economics/yandex/categories.js`
передаёт в него прежний загрузчик и обработчик выбора.
Схема БД не меняется, SQL для этой функции не выполняется.

## Обновление редакции

Справочник — проверенный снимок в репозитории. Автоматического обнаружения
новых редакций на сайте Ozon нет. При изменении тарифов нужно открыть
официальную страницу, проверить дату начала действия, скачать соответствующий
XLSX и импортировать его:

```powershell
.venv/Scripts/python.exe -m scripts.import_ozon_tariffs <xlsx> --source-url <официальная-ссылка> --effective-from YYYY-MM-DD --verified-on YYYY-MM-DD
```

Импорт проверяет заголовки/столбцы FBO, диапазоны процентов, уникальность
идентификаторов, дату и официальный домен. Доли Excel переводятся в проценты
с точностью 8 знаков, убирающей погрешности float. Запись атомарная: ошибка
разбора оставляет прежний файл. Сохраняются URL, SHA-256 файла, лист и строки.
Файл и изменения документации включаются в поставку приложения; после
обновления требуется перезапуск веб-процесса и перезагрузка страницы.

Проверка: 11 временных сценариев (ценовые границы, округление, пропуски,
ручная комиссия, связанные цены, неоднозначность названий, повторяемость
импорта, будущие/неизвестные тарифы, конкурентное чтение, HTTP и права).
Реальный Seller API подтвердил категорию 140729397. Проверки не записывают БД.
Все 41 существующий unittest прошли. Mypy (94 файла), Ruff check и форматирование
12 изменённых Python-файлов прошли; общий format-check обнаружил ранее
неформатированные файлы в 27 посторонних модулях. Смена типа, пересчёт суммы,
ручной процент и сброс проверены в браузере.

Общий выбор категории проверен в браузере 20 октября 2026 года на Ozon и ЯМ:
поиск, отсутствие результатов, переходы по разделам, «Показать ещё», выбор
клавиатурой, закрытие по Escape, ручная комиссия, повторный выбор того же типа,
сброс и переключение компактного/подробного режима. Для Ozon 140729397 переход
со смесителя на современную печатную книгу изменил ставку с 51% на 45%; сброс
вернул 51%. Проверки синтаксиса трёх JS-модулей, загрузки клиентских шаблонов,
Ruff и diff прошли. Сценарии не меняли данные товаров в Ozon или ЯМ.

Автоматический тариф проверен 20 октября 2026 года: 13 временных серверных
сценариев, включая цены 99,99 / 100 / 100,01 / 299 / 300 / 300,01 ₽,
переходы вниз/вверх, исходную низкую цену, все 9308 строк справочника,
неизвестную/нулевую цену, ошибки входа, ручную комиссию, связанные цены,
сумму комиссии, прибыль, ROI и HTTP-права. В Chrome на временной странице
с действующими клиентскими модулями и синтетическими данными подтверждены
эти границы, смена категории и исключение, быстрый ввод, пустое поле,
сброс, повторная отрисовка и переключение режима. Общий ДРР и состав прочей
рекламы сохраняются. Прошли 41 существующий unittest, Ruff check, mypy
(121 файл), форматирование изменённых Python-файлов и синтаксис JavaScript.
Общий `ruff format --check app scripts` отмечает 30 файлов вне этой правки;
они не переформатировались.
Внешний Ozon API, production и PostgreSQL этой проверкой не проверялись;
схема БД и записи не изменяются. Калькулятор по-прежнему моделирует FBO,
отсутствующие в нём FBO Fresh и FBS не добавлены.
