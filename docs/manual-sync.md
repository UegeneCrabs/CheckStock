# Ручные выгрузки

В разделе «API и выгрузки» каждая задача имеет кнопку «Выгрузить вручную».
Доступ определяется активной учётной записью и доступностью раздела интеграции.

Описания задач и подписи расписаний берутся из [каталога метаданных](background-jobs.md#метаданные-каталога-задач):
постоянные значения хранятся в `JOBS` и `SCHEDULE_TEXTS` из `app/core/constants.py`, а
`app/jobs/catalog.py` применяет текущие настройки.

Новый интерфейс получает метаданные через `GET /api/admin/integrations/sync-jobs/catalog`.
Расписание передаётся как `JobScheduleView` из `JOB_SCHEDULE_RULES`; его подпись,
тексты переключателей и оформление статусов формирует frontend. Строки
`SCHEDULE_TEXTS` остаются для старых потребителей каталога.
[JSON-контракты страницы и проверки](ozon-web-contracts.md).

Кнопка вызывает `POST /api/admin/integrations/sync-jobs/{name}/run`.
Ответ `202` содержит идентификатор запуска. Работа продолжается в фоне:
HTTP-запрос и открытая страница не нужны для её завершения.
Страница получает статусы через `GET /api/admin/integrations/sync-jobs` каждые
5 секунд, включая после повторного открытия. Результат и ошибки сохраняются
в обычном журнале `sync_job_runs` с признаком `manual`.

Ручной запуск игнорирует выключатель автовыгрузки, включая отключённый фоновый
режим приложения, но сохраняет выбор магазинов и маркетплейсов. Если не выбрана
ни одна цель, сервер отвечает `409`. Сами настройки при запуске не меняются.

`app/jobs/manual.py` использует обработчики расписания. Исключения нужны для
явного запуска сейчас: Google Таблицы вызывают `run_export`, справочники —
`sync_all(force=True)`, цены WB — `price_sync.sync_stores`, ключи WB —
`refresh_token_info`. Даты закрытия дня, формулы, правила новинок и сохранения
данных остаются внутри существующих загрузчиков. FTP сохраняет прежний пересчёт
следующего запуска; витрина ЯМ при блокировке откладывает попытку до окончания
общей паузы. Остальные ручные запуски не сдвигают расписание.

`app/jobs/tracking.py` удерживает блокировку задачи до завершения. Для PostgreSQL
используется [advisory lock](https://www.postgresql.org/docs/current/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS), общий между контейнерами приложения и сборщика.
Для SQLite используется файловая блокировка в каталоге БД, общая для локальных
процессов. Блокировка освобождается при завершении процесса или соединения.
Ошибки запуска и частичные ошибки загрузчиков записываются в историю.

Заказы Ozon, цены с комиссией FBO, закрытие дневной истории и подробная реклама
запускаются через `app/jobs/async_tracking.py` как `asyncio`-задачи.
До ответа `202` уже получена общая блокировка и сохранён `run_id`.
Вебовый `lifespan` владеет задачей и ожидает её завершение перед закрытием
HTTP-клиента и асинхронной БД. При отмене сохраняется ошибка и освобождается
блокировка, даже если корутина ещё не начала выполняться. Планировщик вызывает
тот же асинхронный обработчик; подробности — [заказы Ozon](background-jobs.md#асинхронные-заказы-ozon).

Автоматическое расписание исполняет отдельный `app.jobs.worker`, а ручные запросы
продолжают выполняться в веб-процессе. Оба используют одну БД и одинаковые имена
блокировок. Успешный ручной запуск не сбрасывает автоматические повторы Ozon и не
сдвигает их срок; исключение — FTP, для которого сохраняется пересчёт следующего
окна. Подробнее: [отдельный планировщик](background-jobs.md).

Цены витрины ЯМ используют общий `run_browser_once` из
`scripts/parsers/parse_yandex_storefront_prices.py`: тот же обычный Chrome/Chromium,
постоянный профиль, проверку паузы и задержку не менее 5 секунд между карточками.
В Windows профиль по умолчанию находится в `data/yandex-storefront/live-check`,
в Linux — `data/yandex-storefront`. Для собственного пути задайте одинаковый
`CHECKSTOCK_YANDEX_STOREFRONT_STATE_DIR` приложению и сборщику.
Между обходами браузер закрыт, профиль освобождён; расписание остаётся прежним.
При включённых прокси в `secrets/yandex_storefront_proxies.json` каждый магазин
использует собственное подключение и профиль внутри `stores/<магазин>` общего
каталога. Ручная кнопка и CLI читают те же настройки, что и расписание.

Локальные паузы на 6 часов после 403 и на час после 429/CAPTCHA отключены.
Старые записи с искусственным сроком больше не блокируют запуск.
Пауза применяется только при явном заголовке `Retry-After` от Яндекса.
Пауза хранится в БД и действует после перезапуска и для всех профилей. Во время
паузы кнопка возвращает `409` с причиной и временем следующей возможной попытки
в МСК, не открывает браузер и не создаёт ещё одну ошибочную выгрузку.
На странице пауза показывается отдельно от результата последней попытки;
кнопка временно недоступна и включается после окончания паузы при обновлении
статуса. Историческая ошибка остаётся до следующего запуска.
Просроченная дата следующего обхода витрины не показывается как будущая:
вместо неё выводится «Сборщик не подтвердил следующий запуск». Дату обновляет
отдельный процесс сборщика. При выключенной автовыгрузке дата скрывается,
а подтверждённый будущий срок учитывает общую паузу после блокировки.

Локально нужны `requirements-parser.txt` и Google Chrome. В Linux без DISPLAY
создаётся частный виртуальный экран Xvfb без сетевого порта, с отдельным окружением
для браузера. В Docker Xvfb включён в образ приложения; оба контейнера работают
от UID 10001 и используют общий том `yandex-parser-data` с прежним профилем сборщика.
Прежний том `yandex-manual-data` не удаляется, но больше не используется.
После обновления пересоберите и перезапустите приложение и сборщик вместе.

Кнопка запускает одну задачу. Добавление кнопок само по себе не выполняет
загрузки и не отправляет данные в Google Таблицы или на FTP.
