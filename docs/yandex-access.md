# Привязка Яндекс Маркета к кабинетам

Для каждого магазина в `secrets/yandex_tokens.json` задайте `api_key` и `business_id`.
Пример структуры: `secrets/example/yandex_tokens.example.json`.
Ключи не должны попадать в Git или логи.

`GET /v2/campaigns` может вернуть магазины нескольких кабинетов, хотя ключ читает
остатки только одного из них. Наличие магазина в этом списке не подтверждает доступ
к его остаткам. `business_id` нужно сверить с кабинетом продавца и проверить чтением
остатков его магазинов.

Выгрузка выбирает только кампании указанного кабинета. Необязательный список
`campaigns` дополнительно ограничивает выбор; все его кампании должны принадлежать
этому кабинету. Без `business_id`, если список кампаний содержит несколько кабинетов
и ограничение `campaigns` не задано, загрузчик проверяет чтение каталога каждого
кабинета через `offer-mappings`. Автоматически выбирается только единственный
кабинет, доступный ключу. Результат проверки кешируется на час отдельно для магазина
и ключа. Если доступных кабинетов несколько или ни одного, загрузка завершается
ошибкой и сохраняет предыдущие данные: нужно явно задать `business_id`.

Каталог и юнит-экономика используют ту же привязку кабинета. Замена ключа через
админку сохраняет `business_id`; при переходе в другой кабинет его нужно изменить
в файле настроек.

Для чтения остатков достаточно доступа `all-methods:read-only` или
`offers-and-cards-management:read-only`.
См. [метод чтения остатков](https://yandex.ru/dev/market/partner-api/doc/ru/reference/stocks/getStocks).

В остатках FBS и FBY по схеме и по складам сохраняется `FIT` — годные товары,
включая резерв. Если `FIT` отсутствует, складываются `AVAILABLE` и `FREEZE`.
Например, 6 доступных и 20 зарезервированных единиц дают остаток 26.
Новое правило применяется при следующей успешной синхронизации схемы.

В карточке товара по складам FBS и FBY видны общий остаток, доступность для заказа
и резерв. Для склада с новым снимком загрузчик сохраняет `AVAILABLE` и `FREEZE`
отдельно, пропущенные типы в записи остатков считаются нулём. Для старых снимков
доступность и резерв показаны прочерками до следующей успешной синхронизации.

При ошибке одной из кампаний прежние остатки соответствующей схемы сохраняются.
Отключённая FBS-кампания не мешает обновлению только при успешном чтении действующей
кампании того же склада. Повтор страницы API завершает выгрузку ошибкой, чтобы не
сохранить неполные или многократно посчитанные данные.
