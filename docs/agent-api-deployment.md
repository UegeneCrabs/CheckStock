# Передача API на сервер компании

Ветка содержит read-only API `/api/agent/v1/`, страницу `/ai-agents`, персональные
отзываемые ключи, автоматическое определение магазина, отчёты экономики, ТЕГ,
новинок, рейтинга и остатков. Данные читаются из существующих источников сайта.
Новые зависимости и миграции схемы БД не добавлены.

## Настройки сервера

- `CHECKSTOCK_AGENT_PUBLIC_URL`: публичный HTTPS origin сайта компании, без завершающего `/`.
- `FORWARDED_ALLOW_IPS`: адреса доверенных прокси для Uvicorn. Если Nginx работает
  на хосте, а приложение в Docker, укажите loopback и фактический gateway сети
  контейнера (на rocketbm.ru: `127.0.0.1,172.18.0.1`). Nginx должен передавать
  `X-Forwarded-Proto $scheme`. Без доверия к gateway HTTPS-запросы воспринимаются
  как HTTP, и создание/отзыв ключей отклоняется проверкой Origin с кодом 403.
  Не используйте `*`; при пересоздании Docker-сети проверьте адрес gateway.
- `CHECKSTOCK_SESSION_COOKIE_SECURE=1`: включить для HTTPS.
- `CHECKSTOCK_AGENT_TOKENS_PATH`: путь к файлу ключей в отдельном постоянном записываемом каталоге.
  Например `/app/agent-credentials/chatgpt_tokens.json`. По умолчанию используется
  `secrets/chatgpt_tokens.json`; стандартный mount secrets:ro не позволяет выпускать ключи через UI.
- Не переносить `.env`, локальную SQLite, ключи пользователей ноутбука и временный Cloudflare tunnel.
- Каталог ключей должен быть доступен только процессу приложения и администраторам.
  Существующие секреты интеграций оставьте read-only. При нескольких экземплярах приложения
  нужен общий каталог ключей с атомарной заменой файлов и эксклюзивным созданием lock-файла.

Пример дополнения Docker Compose (подставить адрес компании через окружение):

```yaml
services:
  app:
    environment:
      CHECKSTOCK_AGENT_PUBLIC_URL: ${CHECKSTOCK_AGENT_PUBLIC_URL:?set company HTTPS origin}
      FORWARDED_ALLOW_IPS: ${FORWARDED_ALLOW_IPS:?set trusted proxy addresses}
      CHECKSTOCK_SESSION_COOKIE_SECURE: "1"
      CHECKSTOCK_AGENT_TOKENS_PATH: /app/agent-credentials/chatgpt_tokens.json
    volumes:
      - agent-credentials:/app/agent-credentials
volumes:
  agent-credentials:
```

Существующие volumes и переменные сохраняются. Обеспечьте владельца/права каталога
для UID приложения. Настройки TLS и применение Compose выполняет команда сервера.

## Проверка после развёртывания

1. Проверить `/healthz`, `/readyz`, вход сотрудника и страницу `/ai-agents`.
2. Выпустить новый ключ на сервере компании для действующего пользователя.
3. Проверить, что `/api/agent/v1/stores` без Bearer возвращает 401, с ключом — доступные магазины.
4. Импортировать `/api/agent/v1/openapi.json` с адреса компании в GPT и настроить новый Bearer.
5. Проверить калькулятор, текущую экономику, рейтинг и `stocks?view=summary` по известному артикулу.
6. Проверить запрет недоступного магазина и отзыв тестового ключа. Не передавать ключ в чате.

`stocks` по умолчанию сохраняет детализацию; `view=summary` возвращает колонки таблицы.
Итог включает транзит. Пропуски и предупреждения нельзя интерпретировать как достоверные нули.

При откате вернуть предыдущую версию приложения. Файл ключей сохранить отдельно;
он не включён в Git.
