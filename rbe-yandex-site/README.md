# RBE Яндекс Маркет

Независимый сайт для отчёта RBE Яндекс Маркета. Он не подключает маршруты,
учётные записи или БД основного CheckStock.

## Что входит

- отчёт RBE по одному магазину или всем магазинам;
- собственная SQLite-база;
- страница ввода API-ключей Яндекс Маркета с проверкой Business ID;
- импорт уже загруженных данных из CheckStock в новую БД одной командой.

## Себестоимость

Страница `/costs` ведёт ежедневные снимки закупочных цен. Она обрабатывает
только вкладки с `WB` в названии в Google Sheets, ищет колонки `АртикулВБ` и
`Себес, руб`, сохраняет все уникальные артикулы и актуальную цену на дату
снимка. Одинаковый артикул с разной ценой на двух вкладках не перезаписывается:
такой конфликт отмечается в журнале загрузки.

Администратор может загрузить Excel (`.xlsx`/`.xlsm`) с теми же колонками или
внести цену вручную. Ручное изменение на конкретную дату не заменяется
последующей автоматической загрузкой Google Sheets; каждая правка попадает в
журнал `cost_changes`.

Источник опубликован с доступом по ссылке, поэтому сервисный аккаунт и
Google API-ключ не нужны. Сервер скачивает публичный XLSX-экспорт таблицы;
если общий доступ будет отключён, загрузка сохранит понятную ошибку в журнале.
По умолчанию ночной снимок создаётся в 02:00 по Москве; время регулируется
`RBE_COST_SYNC_HOUR_MSK`. Кнопка «Загрузить на сегодня» запускает тот же
импорт сразу.

## Автоматическая загрузка и полнота отчёта

Если `RBE_AUTO_SYNC=true`, сначала проверяется вчерашний день во всех магазинах,
затем более ранние даты, от новых к старым, группами до 7 дней. Магазины и типы
отчётов обрабатываются последовательно. Полные прошлые даты из последних
14 завершённых дней перепроверяются не чаще раза в сутки; вчерашний день и
неполные даты — в каждом цикле. Пауза между циклами — 30 минут после обработки.
За цикл запускается не более 12 заданий (`RBE_SYNC_CYCLE_MAX_JOBS`). Ошибка
останавливает более старые запросы этого магазина до следующего цикла, но
не мешает другим магазинам. Даты считаются по московскому времени.

Таблица `sync_retry_days` сохраняет незавершённые даты по магазинам. При запуске
и перед каждым циклом очередь восстанавливается по известной истории, включая
пропуски между датами. Даты старше 90 дней удаляются только из очереди,
а сохранённые отчёты и финансовые данные остаются. Такие даты также запрещены
для ручной загрузки и в отдельном загрузчике. В пределах доступных 90 дней
ошибки API, `NO_DATA` и успешный, но неполный ответ оставляют
даты в очереди. Отсутствующие закупочные цены исправляются отдельно на странице
себестоимости: повтор API Маркета их не заполнит.

Раскрываемая очередь на сайте показывает тип ожидания, магазин, дату, причину
и последнюю попытку. `sync_day_checks` хранит причины и время успешной загрузки.
Для старых заданий без сохранённой причины явно показывается неизвестная причина.
Плановая сверка полных дней не обозначается как отсутствие данных.

RBE запрашивает список заказов только за выбранный период создания: дополнительное
окно в 90 дней здесь не нужно, поскольку выкупы и возвраты берутся из финансовых
отчётов. Поведение основного CheckStock при этом не меняется. Повторное чтение
локальных архивов для устранения дублей возврата не является запросом к API.

Кнопка «Обновить по API» доступна администратору и повторно запрашивает весь
выбранный период для выбранного магазина (или всех), включая зелёные строки.
Маленькие кнопки рядом с неполными показателями запрашивают только пропуски.
Оба варианта показывают результат попытки, а незавершённая работа сохраняется
после перезапуска. Для одного магазина выдерживается минимум 125 секунд после
предыдущей попытки; общий lock не допускает параллельных ручных и фоновых импортов.
При частичном сбое в RBE копируются только успешно обновлённые магазины.

Исторические исправления API обнаруживаются повторным запросом, а не уведомлением
от Яндекса. Последние `RBE_SYNC_LOOKBACK_DAYS` дней обновляются даже при полном
статусе. Успешная загрузка заменяет расчёты за этот период и пересчитывает зависимые
суммы. Более старые **полные** периоды автоматически не перепроверяются: для них
используйте кнопку обновления. Зелёный статус не означает неизменность данных.

Настройки окружения:

```text
RBE_AUTO_SYNC=true
RBE_SYNC_INTERVAL_MINUTES=30
RBE_SYNC_LOOKBACK_DAYS=14
```

Под каждым показателем RBE отображает статус его исходных данных. Для
«ТО заказы из воронки» проверяются ежедневные данные заказов, для остальных
строк — ежедневные финансовые данные. Если день или магазин отсутствует,
сайт выводит точный неполный период вместо того, чтобы показывать результат
как полный.

## Доступ пользователей

Сайт закрыт авторизацией. Файл пользователей хранится только в
`secrets/users.json` и исключён из Git. Создайте администратора и пользователей
на новом сервере интерактивной командой — пароль не попадёт ни в shell history,
ни в исходный код:

```powershell
python scripts/create_user.py rbe-admin admin
python scripts/create_user.py rbe-test-01 viewer
```

Роль `admin` видит отчёты и управляет ключами API. Роль `viewer` видит только
отчёты. Сессия действует 12 часов; этот срок меняется через
`RBE_SESSION_TTL_HOURS`.

## Локальный запуск

```powershell
cd rbe-yandex-site
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
..\.venv\Scripts\python.exe scripts\import_from_checkstock.py ..\data\checkstock.db
..\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8060
```

Откройте `http://127.0.0.1:8060`.

### Windows: запуск без открытого терминала

Если сервер уже запущен в CMD, сначала остановите его сочетанием `Ctrl+C`.
Затем дважды нажмите `start-background.cmd` в папке сайта. Он запускает
сервер скрытым отдельным процессом и открывает сайт после проверки готовности.
После этого окно запуска можно закрыть; журнал сохраняется в
`data/server-logs/`. Если порт 8060 занят, команда не останавливает чужой
процесс и не запускает вторую загрузку данных.

Это фоновый запуск, не служба Windows: после перезагрузки компьютера или
выхода из учётной записи запустите файл снова. Во время сна компьютера сайт
и загрузка данных недоступны. Для остановки откройте Диспетчер задач,
найдите процесс Python с командной строкой `-m uvicorn main:app --host
127.0.0.1 --port 8060` и завершите только этот процесс.

## Изоляция при развёртывании

Папки `data/` и `secrets/` не попадают в Git. Для сервера создайте их рядом с
приложением и задайте `RBE_DATABASE_PATH` и `RBE_CONNECTIONS_PATH` абсолютными
путями. В исходный код и логи API-ключи не попадают.

## Полнота финансовых данных

Наличие строки расчёта не подтверждает готовность исходных отчётов. При импорте
сохраняется отдельная таблица `daily_source_quality` для каждого кабинета и дня.
Непроверенные старые строки, отсутствие отчёта по услугам и дни после последней
даты операций в отчёте получают статус «Неполные». Нулевой день внутри периода,
для которого уже есть более поздние операции, допустим. Доставки без операций
`payment_transfer` требуют дополнительной загрузки. Это консервативная проверка
доступных источников, а не гарантия отсутствия будущих корректировок Яндекса.
Полностью пустой отчёт сам по себе не подтверждает нулевые финансовые показатели.
ЗЦ и прибыль наследуют неполноту финансовых данных. Ответ `NO_DATA` не считается
успешным заполнением дня. Запросы за недостающие дни не исправляют цены вручную.

Для существующей базы после обновления кода один раз заполните только метаданные
качества (без API-запросов и пересчёта сумм), от пользователя `rbe`:

```sh
/opt/rbe/venv/bin/python /opt/rbe/code/rbe-yandex-site/report_quality.py \
  --source /opt/rbe/shared/data/checkstock.db \
  --target /opt/rbe/shared/rbe-yandex-site/data/rbe_yandex.db
```

Миграция повторяемая. Новые загрузки записывают качество вместе с расчётами.
Метаданные с другой датой расчёта не дают зелёный статус устаревшим суммам.
