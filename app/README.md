# Код приложения

В корне остаются точки входа и сборки: `main.py`, `config.py`, `container.py` и общий фасад доступа к данным `db.py`.

| Папка | Назначение |
|---|---|
| `access` | Аутентификация, права, доступ к разделам и уведомления. |
| `agents` | Ключи, отчёты и калькулятор API ИИ-агентов. |
| `core` | Общие типы, магазины, форматирование, ошибки, журналы и состояние системы. |
| `stock` | TOTAL, идентификация товаров, история, поставки и складские отчёты. |
| `orders` | Общая загрузка и нормализация заказов маркетплейсов. |
| `economics/wb` | Расчёты WB, цены, реклама, история и отчёты экономики. |
| `economics/yandex` | Агрегация показателей экономики ЯМ. |
| `economics/sources` | Импорт исходных данных и закупочных цен. |
| `exports` | Выгрузки на FTP и в Google Таблицы. |
| `jobs` | Отдельный worker автоматических загрузок, сохранённые расписания, ручные запуски и блокировки. |
| `integrations` | Общие доступы маркетплейсов и уведомления Битрикс. |
| `wb`, `ozon`, `yandex` | API и синхронизация конкретных площадок. |
| `ff_import` | Разбор таблиц и файлов складских операций. |
| `application` | Прикладные сценарии и интерфейсы доступа к данным. |
| `dto` | Модели входных и выходных данных. |
| `infrastructure` | Подключение к БД, ORM и прикладные репозитории; общие async-ресурсы и HTTP-транспорт. |
| `repositories` | SQL-запросы, снимки данных и схема БД. |
| `web` | HTTP-маршруты, middleware и формирование страниц. |

Код раздела обычно проходит через `web/routers`, предметную папку и `repositories`. Отображение находится в соответствующих разделах корневых `templates` и `static`.
